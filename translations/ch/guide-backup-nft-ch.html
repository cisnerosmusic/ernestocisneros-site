Foundation 关闭前NFT 备份指南

分步指南，确保您的作品不会随市场平台一起消失。区块链会记住，但文件需要有人维护。

作者：Ernesto Cisneros Cino · 作曲家、加密艺术家、Impulses.art 创始人 · 2026 年 4 月

Foundation 即将关闭。代币会永久保留在区块链上，但组成代币的文件（图像、视频、元数据）存放在 IPFS 上，固定在 Foundation 的节点上，这些节点最终将会下线。届时，链接将无法解析，作品将成为视觉上孤立的代币，尽管链上的其他信息仍然存在。

本指南将带您通过一个独立的去中心化固定服务来备份您的整个作品集，无需支付任何费用。完成后，您的作品将受到您自己控制的基础设施保护，而不是依赖可能明天就关闭的公司。

根据作品数量不同，整个过程需要 30 分钟到 2 小时。每一分钟都值得投入。

步骤 01

您需要做什么

开始之前理解问题和解决方案，可以避免后续的困惑。

问题

当您在 Foundation 上铸造作品时，智能合约在 Ethereum 上保存了一个CID（Content Identifier，内容标识符）引用，指向 IPFS 上的元数据 JSON 文件。该 JSON 包含标题和描述，并通过另一个 CID 指向实际的图像或视频文件。

代币本身是永久的。但是 CID 文件只在某个 IPFS 节点持续固定它们时才存在。Foundation 将这些文件固定在自己的节点上。当这些节点关闭后，如果没有人继续固定这些文件，它们将从网络中消失。

解决方案

您需要将这些相同的 CID 固定在自己的节点上（实际上是一个充当您节点的免费服务）。这不是将文件复制到其他地方，而是在同一 IPFS 网络内强化它们的存在。CID 保持不变，作品保持不变，但现在多了一层冗余：文件同时存在于 Foundation 的节点和您的节点上。

当 Foundation 关闭其节点时，您的节点仍然活跃。IPFS 链接继续工作。您的作品在市场平台关闭后依然存在。

重要

Ethereum 代币（您的所有权、交易历史、销售记录）从未面临风险。处于风险中的是视觉和描述层。本指南保护的正是这一层。

步骤 02

为什么选择 Filebase

Pinata 是行业先驱，但其免费计划已不再适用于这一具体场景。Filebase 是务实的替代方案。

Pinata 对我们所需的确切功能（Import from IPFS，固定现有 CID）收费。在免费计划中，您只能从计算机上传新文件，无法固定网络上已存在的 CID。

Filebase 提供5 GB 存储空间、最多 1,000 个文件、专用网关、Import CID 功能，全部免费包含在计划中，无需信用卡。比 Pinata 多五倍的空间，关键功能没有限制。

Filebase 还使用地理上分散位置的 3 倍冗余，这是真实的冗余，而非营销话术。

说明

Pinata 并非不好的服务。只是您的使用场景（固定已铸造的作品）恰好是其当前商业模式推向付费计划的功能。Filebase 将同样的场景视为合法的免费使用。

步骤 03

创建免费 Filebase 账户

五分钟，无需信用卡。

  1. 访问 filebase.com，点击 Get Started Free 或 Sign Up。
  2. 输入您的邮箱并创建强密码。不需要任何卡片或账单信息。
  3. 通过收到的邮件链接确认账户。
  4. 使用用户名和密码登录控制台。

您将看到空的工作空间。界面仅提供英文，但操作流程简单。

步骤 04

创建归档 bucket

bucket 相当于存放固定文件的文件夹。

  1. 在控制台侧边栏点击 Buckets。
  2. 点击 Create Bucket。
  3. 设置一个唯一名称，例如 your-name-nft-archive。bucket 名称是全局管理的，如果已被使用，需要选择其他名称。
  4. 在 Network 中选择 IPFS。不要选择 Sia 或其他网络，Foundation NFT 备份需要 IPFS。
  5. 点击 Create 确认。
关于 S3 Private 与 Public

Filebase 会显示公开 bucket 需要付费计划的提示。请忽略此提示，保持 S3 Private 设置。该提示涉及的是 S3 访问（Amazon 协议），与 NFT 无关。您的文件仍可通过任何 IPFS 网关的 CID 公开访问：ipfs.io、dweb.link、cloudflare-ipfs.com。bucket 的 Private 设置不会影响这一点。

步骤 05

获取每个作品的 CID

每个作品有两个 CID 需要识别：元数据 JSON 的 CID 和图像或视频文件的 CID。

方法 1：从 Foundation 获取（趁其仍可访问）

  1. 进入您的 Foundation 个人资料，打开其中一个作品。
  2. 在 Details 或 Token Details 选项卡中找到 IPFS 或 Metadata 链接。
  3. 格式类似于：https://ipfs.io/ipfs/QmXX.../metadata.json。保存此链接。
  4. 元数据 CID 是 /ipfs/ 和 /metadata.json 之间的部分：QmXX...

方法 2：打开 JSON 提取媒体 CID

在浏览器中打开 JSON 文件，您会看到类似内容：

JSON 元数据 { "name": "您的作品", "description": "...", "image": "ipfs://QmYY.../nft.mp4" }

image 字段的值（有时是 animation_url）以 ipfs:// 开头，后面跟着另一个 CID。这就是媒体 CID。也请保存。

制作简单的清单表格

对每个作品，记录以下信息：

  • 作品标题
  • 元数据 JSON 的 CID
  • 媒体文件（视频或图像）的 CID
  • 合约地址和 TokenID（用于后续在 Etherscan 上搜索）

简单的电子表格即可。请在 Foundation 仍可访问时完成此操作。稍后提取数据可能会显著更加困难。

提示

如果您的 Foundation 个人资料中有易于复制的清单，请批量提取。您也可以在 Etherscan 上搜索您的钱包并按 NFT 筛选，直接查找您的代币。

步骤 06

在 Filebase 上固定您的 CID

这一步是实际备份的关键。Filebase 在 IPFS 网络中找到您的文件并复制到其节点上。

每个作品的操作流程

  1. 点击 bucket 名称打开您创建的 bucket。
  2. 您会看到三个选项：Import CID、New Folder、Upload。点击 Import CID。
  3. 弹出表单。粘贴第一个作品的元数据 JSON CID。
  4. 设置描述性名称，例如 my-artwork-metadata.json。
  5. 点击 Search and Pin 确认。

Filebase 会在 IPFS 网络中搜索该 CID（需要几秒钟），并将其固定到其节点上。状态将从 Pinning（进行中，橙色图标）变为 Pinned（已确认，绿色图标）。

对媒体文件 CID 重复相同步骤：

  1. 再次点击 Import CID。
  2. 粘贴视频或图像 CID。
  3. 命名：my-artwork-media.mp4（或正确的扩展名）。
  4. 确认。

建议的命名规范

使用一致的命名方式，便于日后浏览 bucket。建议：

  • 独立作品：artwork-title-metadata.json 和 artwork-title-media.mp4
  • 合作作品：split-collaborator-name-title-metadata.json
  • 编号系列：series-01-title-metadata.json、series-02-...（超过 9 个时前面加零）

使用小写字母，用连字符代替空格，不使用特殊字符或变音符号。这可避免 URL 和文件系统问题。

预计时间

每次固定操作需要几秒钟（小型 JSON）到几分钟（大型视频）。对于 10-15 个作品的作品集，预计需要 40 分钟到 1 小时的手动操作时间。

值得关注的细节

如果您固定的 CID 已被 Filebase 固定在其他地方（例如另一位艺术家固定了相同文件），固定过程几乎即时完成。IPFS 不复制文件，而是强化文件的存在。

步骤 07

验证一切正常

将备份视为完成之前，请确认文件确实可从公共网络访问。

验证 1：所有文件都显示 Pinned 状态

查看 bucket 中的 Status 列。所有文件应显示绿色图标和 Pinned 标签。如果某个文件在几分钟后仍为 Pinning（橙色），请稍等或刷新页面。

验证 2：可通过公共网关访问

复制任一 CID，粘贴到以下 URL 中，将 [CID] 替换为实际 CID：

测试 CID https://dweb.link/ipfs/[CID]

如果显示内容（JSON 或视频），说明您的 pin 在去中心化网络上处于活跃状态，可从任何网关访问，不依赖 Foundation 或 Filebase。

验证 3：合理的存储使用量

查看 bucket 的 Storage 指示器。典型的 NFT 视频大小为 10 到 80 MB 之间。如果您有 15 个带视频的作品，大约占用 500-800 MB。距离免费计划的 5 GB 限制还有充足空间。

如果接近限制（因为作品较多或视频很大），可以考虑仅固定不太重要作品的元数据，而不额外备份视频（这些视频会在其他公共 IPFS 节点上保留一段时间）。

步骤 08

更新网站链接

如果您有个人网站或作品集链接到 NFT，这些链接需要更改。指向 Foundation 的链接将失效。

需要替换的内容

在您的网站上查找类似以下的链接：

https://foundation.app/mint/eth/0x...../tokenID https://fnd-collections.mypinata.cloud/ipfs/QmXX.../metadata.json https://fnd-collections4.mypinata.cloud/ipfs/...

这些都将停止工作。应替换为稳定的 IPFS 网关链接。

应使用的链接

建议每个作品使用三种链接类型：

1. 元数据（作品的技术记录）：

https://dweb.link/ipfs/[CID_METADATA]/metadata.json

2. 媒体（视频或图像）：

https://dweb.link/ipfs/[CID_MEDIA]/nft.mp4

3. Etherscan（链上所有权验证）：

https://etherscan.io/token/[CONTRACT]?a=[TOKEN_ID]

第三个链接替代 Foundation 链接。之前指向市场平台的位置，现在指向永不关闭的 Ethereum 公共登记处。

关于网关

我使用 dweb.link，因为它由 Protocol Labs（非营利基金会）运营，速度相对较快且中立。有效替代方案：ipfs.io（同一运营方，有时较慢）、cloudflare-ipfs.com（速度快但依赖中心化公司）。任何一个都可以使用，关键是 CID。

步骤 09

作品位于 Arweave 的情况（无需备份）

部分 Foundation 作品使用 Arweave 而非 IPFS。这种情况下持久性是内置的。

如果打开作品的元数据时，您看到以 arweave.net 结尾的 URL，或以哈希值加 .arweave.net 开头的 URL，说明您的作品位于 Arweave 上，而非 IPFS。

Arweave 是另一种去中心化存储网络，采用不同的模型：您在铸造时一次性付费，存储通过一个持续向节点付款的捐赠基金在约 200 年内得到保障。

实际结论：如果您的某件作品位于 Arweave 上，无需备份。其持久性在结构上得到保证。在清单中标记即可，然后继续处理其他作品。

步骤 10

Foundation 完全关闭之前

关闭前的最后操作。

下架未售出的作品

如果您在 Foundation 上有尚未被购买的挂单作品，建议在关闭前下架。这会将代币从 Foundation 的托管合约中释放出来，并返回到您的钱包（或铸造者的钱包）。需要支付少量 gas 费，但可以避免关闭后的复杂情况。

通知合作者

如果您有链上分成的作品，请提醒您的合作者也在自己一方进行备份。分成在合约存在期间保持有效，但文件需要多个节点的支持才能继续存在。

导出策展信息

Foundation 保存了不在链上的信息：包含收藏者姓名的销售历史、编辑说明、准确的拍卖日期、出价记录、关注者列表。所有这些信息将随 Foundation 一同消失。请在关闭前截屏或尽可能导出。

记录您自己的历史

如果您多年来活跃于加密艺术领域，您是极少数从内部亲历这段文化历史的人之一。请记录下您记得的内容。活动照片、社区成员姓名、倒下的平台、受禁运影响的艺术家遭遇的封禁。这份叙事档案与 CID 同等重要。

完成后

固定所有作品、确认公共访问、更新网站链接后，您的作品集将在 Foundation 关闭后继续存在。

步骤 11

如果 Filebase 有一天关闭会怎样

合理的问题。如果您备份是为了不依赖 Foundation，那是否只是将依赖转移到了另一家公司？

简短的回答

如果 Filebase 明天关闭，您的文件不会立即消失。IPFS 通过积累复制相同内容的节点来运作，而不是通过单一故障点。Filebase 关闭只会移除您文件的一份副本，而不是全部。

此外，CID 是通用的，不属于 Filebase。如果明天您在另一家提供商处开设账户并粘贴相同的 CID，几分钟内即可再次拥有活跃的备份。步骤 05 中建立的清单就是迁移所需的全部资料。

IPFS 上持久性的实际运作方式

IPFS 上的文件只要至少一个节点主动固定，就会持续存在。当 Filebase 固定您的 CID 时，其节点（通常在不同位置三倍复制）使文件保持活跃。

但 Filebase 并不是唯一持有您文件的地方。每次有人访问 IPFS 网关并加载您的作品时，该网关都会临时缓存。每次交互都留下短暂的副本。Foundation 在关闭之前仍会保持您的 CID 固定。网络具有自然的复制惯性。

Filebase 关闭的三种可能情景

情景 1，提前通知的关闭（预期的情况）：严肃的服务商会提前数周或数月通知。您有充足时间迁移到其他提供商：4EVERLAND、Web3.Storage、Lighthouse。由于您已有 CID 清单，迁移很简单：开设账户，导入相同的 CID，继续使用。

情景 2，无预警的突然关闭：可能性较低但存在。只有在同时没有其他节点持有该文件的情况下，文件才会丢失。对于有任何活动的文件，这在统计上非常罕见。

情景 3，被其他公司收购（最常见）：较大的公司收购较小的公司，并以新条款继续提供服务。过渡期间您的 pin 保持活跃。近期生态系统中的案例：KnownOrigin 被 eBay 收购，政策发生重大变化，但此前铸造的文件技术上仍可访问。

稳健的策略：多提供商冗余

哲学上正确的做法不是仅相信 Filebase 不会关闭，而是不完全依赖 Filebase。可以逐步实施四个保护层级：

层级 1，当前状态：Filebase 上的活跃 pin。5 GB 免费。满足标准需求。

层级 2，并行冗余：在其他提供商处开设第二个免费账户，复制相同的 pin。稳健的选择：

  • 4EVERLAND：5 GB 免费，界面简洁，不同的提供商。
  • Web3.Storage：来自 Protocol Labs（IPFS 的创建者）。5 GB 免费，机构上非常稳定。
  • Lighthouse：一次性付款的永久存储模型，使用 Filecoin 作为经济层。

相同的 CID 固定在两个不同的提供商处，其中一个关闭不会影响另一个。

层级 3，本地物理副本：将所有媒体文件按文件夹整理下载到硬盘或外置磁盘。不用于公共链接，但确保即使世界上所有节点都失败，您仍拥有原始文件。这是认真的档案管理者的最后防线备份。

层级 4，可选、高级：使用 IPFS Desktop 或 IPFS CLI 在自己的机器上运行自己的 IPFS 节点。最大的技术自主性。节点仅在计算机开启时活跃，因此作为托管服务的补充而非替代。

实际建议

目前仅保留 Filebase（层级 1）即可满足短期真实风险。Filebase 自 2019 年起运行，目前看起来比其他服务机构上更稳定。

3 到 6 个月后，如需强化，可在 4EVERLAND 或 Web3.Storage 上开设账户并复制 pin。由于已有包含所有 CID 的清单，只需 15 分钟即可实现真实冗余。

硬盘本地副本可在有时间时进行，并非紧急但值得做。自建 IPFS 节点仅推荐给喜欢管理基础设施的用户。

重要区分

中心化和依赖是不同的。Filebase 是中心化提供商（私营公司、自有服务器），但您对 Filebase 的使用是可解耦的。CID 是 IPFS 标准，清单保存在您自己的磁盘上，您可以随时迁移到其他提供商。这与对 Foundation 的依赖根本不同。Foundation 关闭意味着失去链接、叙事、个人资料和社区。这一次，任何关闭都只是不便，而非灾难性的。这是真正的进步。

常见问题

常见问题

关于 Foundation 关闭和 NFT 保存的常见问题，简明直接的解答。

Foundation 关闭后我的 NFT 会怎样？

代币永久保留在 Ethereum 上，完好无损。处于风险中的是链下层：目前存放在 Foundation IPFS 节点上的 JSON 元数据和媒体文件（图像、视频）。这些节点下线后，如果不将文件固定到其他服务上，文件可能无法访问。您的所有权是安全的，但视觉表现需要备份。

我需要将 NFT 迁移到其他区块链吗？

不需要。无论 Foundation 命运如何，NFT 都保留在 Ethereum 上。Foundation 是市场平台界面，Ethereum 是底层区块链。您只需备份链下文件，无需迁移代币本身。

Filebase 真的对 NFT 备份免费吗？

是的。5 GB 存储、最多 1,000 个固定文件、专用 IPFS 网关、Import CID 功能，全部免费，无需信用卡。这正是 Pinata 转移到付费计划的功能组合。

什么是 IPFS CID，为什么重要？

CID（Content Identifier）是基于内容唯一标识 IPFS 文件的加密哈希。您的 NFT 智能合约保存指向元数据的 CID 引用，元数据则指向媒体的 CID。CID 只在节点固定文件时才能解析出内容。没有 pin，无论代币是否存在，都没有内容。

如果 Filebase 也关闭怎么办？

步骤 11 中详细讨论。简要：CID 是通用的，您可以使用清单在几分钟内迁移到其他 IPFS 提供商（4EVERLAND、Web3.Storage、Lighthouse）。为提高稳健性，使用多提供商冗余。

Foundation 关闭前是否应下架未售出的 NFT？

建议如此。下架会将代币从 Foundation 的托管合约中释放出来，返回给铸造者的钱包，使其可在未来在其他地方重新挂单。需要少量 gas 费，但可以避免复杂情况。

整个备份过程需要多长时间？

对于 10-15 个 NFT，预计 30 分钟到 2 小时。JSON 元数据几秒钟内固定完毕。视频文件每个可能需要几分钟。CID 清单准备好后，流程虽重复但不复杂。

如果我的 NFT 位于 Arweave 而不是 IPFS 怎么办？

无需备份。Arweave 按设计提供永久存储：铸造时一次性付款，通过持续向节点付款的经济捐赠基金保存约 200 年。

本指南适用于 Foundation 以外的艺术家吗？

是的。相同流程适用于 Ethereum 上任何元数据和媒体位于 IPFS 上的 NFT。SuperRare、Zora、Objkt、KnownOrigin（关闭前）、Rarible：流程相同，只是 CID 来源不同。

作为收藏者可以固定其他艺术家的 NFT 吗？

可以，而且鼓励这样做。CID 按设计是公开的。固定您收藏的 NFT 可保护您的收藏免受原始节点失败的影响。特别是有直接联系时，出于礼貌考虑通知艺术家。

技术扩展

运行自己的 IPFS 节点

本节适用于有一定技术基础、追求更高自主性的艺术家。对作品备份本身并非必需（Filebase 已足够）。如果您希望不依赖任何提供商，这里是实现路径。

拥有自己节点的意义

IPFS 节点是作为网络参与者运行的计算机。安装软件后，您的机器可以固定文件、向全球提供文件，无需依赖任何商业服务即可维护。您从提供商的客户转变为网络的完全参与者。

与 Filebase 的主要区别：使用 Filebase 时，您请求公司将文件固定在其服务器上。使用自己的节点时，您就是服务器。

重要权衡

节点仅在计算机开启并连接到互联网时提供文件。关机后，您的文件会在网络其他节点（Filebase、公共网关、其他固定服务）上继续存在，但您不再做出贡献。为实现真正的永久备份，节点应几乎始终保持活跃。

两条实际路径，取决于所需控制级别

路径 A：IPFS Desktop（最易上手）

在 macOS、Windows、Linux 上像其他程序一样安装的图形应用。5 分钟设置，图形界面，无需命令行。适合实验和学习。

优点：安装简单，图形界面，不用时可关闭应用。
缺点：运行时消耗 RAM（200-400 MB），依赖不被意外关闭，关机时可用性丢失。

路径 B：专用 Raspberry Pi（认真的方案）

购买 Raspberry Pi（含外壳、电源、SD 卡约 75-120 USD），安装 IPFS，在家中连接路由器 24/7 运行。专用永久节点，电力消耗相当于 LED 灯泡（5-10 瓦，每月约 2-3 USD）。

优点：真正的永久节点，不占用主计算机资源，完全的技术自主。
缺点：需要初始购买，更复杂的技术安装（命令行），为外部访问配置路由器。

建议

从 IPFS Desktop 开始。无需经济投入即可学习概念。几周后若觉得确实在使用且希望真正的永久性，再评估是否投资专用 Raspberry Pi。

IPFS Desktop 分步操作

步骤 1：下载安装程序

访问 ipfs.tech/install/ipfs-desktop/（项目官方域名）。选择适用于您操作系统的安装程序：macOS、Windows 或 Linux。

步骤 2：安装

在 macOS 上打开 .dmg 并将图标拖到应用程序文件夹。在 Windows 上运行 .exe。在 Linux 上通常是 .AppImage。在 macOS 上首次运行时系统可能警告开发者未验证：进入"系统偏好设置 → 安全性"手动授予权限。这是正常的，并不意味着软件不安全。

步骤 3：首次运行

首次打开应用程序时会自动完成三件事。首先，为您的节点创建唯一的加密身份（网络上您节点的永久标识）。其次，连接全球 IPFS 网络，几秒内显示数十到数百个连接的对等节点（peers，即其他节点）。再次，打开包含五个标签的界面：Status、Files、Explore、Peers、Settings。

步骤 4：固定第一个 CID

进入 Files 标签。顶部有 Import 按钮。点击后展开选项菜单。选择 From IPFS（有时显示为 Add by CID 或 Import from IPFS）。粘贴一个 CID 并确认。

节点将开始从持有该文件的其他节点（Filebase、公共网关、任何活跃来源）下载文件。几秒到几分钟后（取决于大小），文件本地固定完毕。此时您的计算机成为支持该 CID 的网络成员之一。

步骤 5：验证是否正常工作

两项简单验证。第一，Files 中应显示带有 pin 图标和下载大小的 CID。第二，在浏览器中打开：

本地网关 http://localhost:8080/ipfs/[your-CID]

localhost:8080 是您节点自身运行的本地网关。如果显示内容，说明节点正在活跃提供文件。这是真正的技术自主性。

步骤 6：固定作品集其余部分

对清单中所有 CID 重复该过程。对于 10-15 个作品，根据连接速度预计 30 分钟到 2 小时。

日常使用的实际考虑

资源消耗：IPFS Desktop 活跃时使用 200-400 MB 内存。现代计算机上不是问题，但在内存较小的机器上会明显。可在 Settings 中配置限制。

带宽：节点不仅下载，还向请求文件的其他节点上传。连接受限时在 Settings 中配置限制。普通家庭连接下不会察觉。

关闭计算机：只要其他节点保持固定，您的 CID 在网络上保持活跃（Filebase 作为备份）。节点只是暂时停止贡献。重新开机时自动恢复。

磁盘空间：每个固定的 CID 在本地磁盘上占用其大小。计算：500 MB 的 Foundation 作品集，节点占用 500 MB。大型 Tezos 作品集可能达到几 GB。请确认磁盘有足够空间。

具体获得什么

  • 真正独立于 Filebase：明天 Filebase 关闭且节点保持活跃的情况下，文件无需您干预即可继续访问。
  • 无中介发布：创建新作品并希望将其固定到 IPFS 而不经过任何服务时，可直接从节点操作。
  • 对系统的技术理解：运行节点即便只是几周，也能获得大多数 NFT 艺术家从未获得的生态系统理解。
  • 对生态系统的贡献：每增加一个节点都加强了整个 IPFS 网络。您的参与不仅是自我保护，也是社区行为。

向 Raspberry Pi 的自然演进

在 IPFS Desktop 上实验后，若希望真正的永久性，自然路径是：

  1. 购买 Raspberry Pi 4（4 或 8 GB 内存）、电源、外壳、128 GB microSD 卡。总计约 100-150 USD。
  2. 通过以太网线缆连接到家中的路由器，放置于房屋的一角。
  3. 按照 Raspberry Pi 专用教程（英文资源丰富，部分中文）安装 IPFS。
  4. 配置断电后自动重启，保持节点始终活跃。
  5. 高级选项：配置指向 Raspberry Pi 的子域名（例如 ipfs.yourartist.art），建立自己的网关。

最后这一步，使用自己的域名建立自己的网关，是最大的自主性。不再依赖 dweb.link 或 ipfs.io。网站链接将属于您自己：ipfs.yourartist.art/ipfs/[CID]/file.mp4。

需要明确说明

拥有自己的节点不会替代 Filebase，也不会使您已完成的工作变得多余。这是补充。理想策略结合三者：Filebase 作为始终活跃的托管备份，加上 IPFS Desktop 或 Raspberry Pi 作为从您自己基础设施加强的自建节点，加上硬盘本地副本作为最后防线档案。三个冗余层，每层由不同设计保护。
