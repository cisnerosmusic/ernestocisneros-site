Foundation закривається. Токени назавжди залишаться у блокчейні, але файли, з яких вони складаються (зображення, відео, метадані), знаходяться на IPFS, запіннені на вузлах Foundation, які рано чи пізно будуть вимкнені. Коли це станеться, посилання перестануть працювати, а твори перетворяться на візуально осиротілі токени, навіть якщо все інше on-chain залишиться на місці.

Крок 01

Що саме Ви зробите

Розуміння проблеми та рішення перед початком роботи вбереже Вас від плутанини далі.

Проблема

Коли Ви мінтували твір на Foundation, смартконтракт зберіг посилання в Ethereum (це CID, Content Identifier), що вказує на Ваш JSON-файл метаданих на IPFS. Цей JSON містить назву, опис, а також через інший CID вказує на реальний файл зображення чи відео.

Токен постійний. Але файли CID існують лише поки якийсь вузол IPFS тримає їх запінненими. Foundation тримав їх запінненими на своїх вузлах. Коли ці вузли будуть вимкнені, якщо більше ніхто ці файли не пінить, вони зникнуть з мережі.

Рішення

Ви запінните ті самі CID на Вашому власному вузлі (фактично на безкоштовному сервісі, що діє як Ваш вузол). Це не копіювання файлів кудись в інше місце, це посилення їх існування всередині тієї самої мережі IPFS. CID залишається тим самим, твір залишається тим самим, але тепер у нього є надлишковість: він живе на вузлах Foundation і на Ваших.

Коли Foundation вимкне свої вузли, Ваші залишаться активними. Посилання IPFS продовжать працювати. Ваша робота переживе закриття маркетплейсу.

Важливо

Токен Ethereum (Ваша власність, історія, продажі) ніколи не під загрозою. Під загрозою знаходиться візуальний та описовий шар. Саме цей шар ми і зберігаємо.

Крок 02

Чому Filebase, а не Pinata

Pinata був першопрохідцем, але його безкоштовний план більше не працює для цього конкретного випадку. Filebase, чесна альтернатива.

Pinata бере плату саме за ту функцію, яка нам потрібна (Import from IPFS, пінінг існуючих CID). На безкоштовному плані Ви можете лише завантажувати нові файли з Вашого комп’ютера, але не пінити CID, які вже існують у мережі.

Filebase пропонує 5 ГБ сховища, до 1000 файлів, виділений шлюз та функцію Import CID, все включено в безкоштовний план без банківської картки. Це в п’ять разів більше простору, ніж у Pinata, і ключова функція без обмежень.

Filebase також використовує трикратну надлишковість у географічно різних місцях, і це реальна надлишковість, а не маркетингові слова.

Філософська нотатка

Pinata не поганий сервіс. Справа в тому, що Ваш сценарій (пінінг уже створених творів), саме те, що їхня поточна бізнес-модель переводить у платні тарифи. Filebase ставиться до цього сценарію як до законного безкоштовного використання.

Крок 03

  4. Увійдіть до панелі керування з Вашим іменем користувача та паролем.

Ви побачите свій порожній робочий простір. Інтерфейс чистий, лише англійською, але процес простий.

Крок 04

Створіть архівний бакет

Бакет це як папка, у якій житимуть Ваші піни.

  1. У панелі керування натисніть Buckets у бічній навігації.
  2. Натисніть Create Bucket.
  3. Дайте йому унікальне ім’я, наприклад vashe-imya-nft-archive. Імена бакетів є глобальними, тому якщо Ваше зайняте, потрібно буде вибрати інше.
  4. У полі Network оберіть IPFS. Не обирайте Sia чи інші мережі, Вам потрібен IPFS для Ваших NFT з Foundation.
  5. Підтвердьте натисканням Create.
Про S3 Private та Public

Filebase покаже сповіщення, що публічні бакети потребують платного плану. Проігноруйте його, залиште на S3 Private. Це сповіщення стосується доступу S3 (протокол Amazon), який не використовується NFT. Ваші файли все одно будуть публічно доступні за CID з будь-якого шлюзу IPFS: ipfs.io, dweb.link, cloudflare-ipfs.com. Налаштування приватного бакету це не обмежує.

Крок 05

Отримайте CID кожного твору

У кожного твору є два CID для ідентифікації: один для JSON метаданих, інший для файлу зображення або відео.

Метод 1: З Foundation (поки він ще працює)

  1. Зайдіть у Ваш профіль Foundation і відкрийте одну з Ваших робіт.
  2. Під вкладкою Details або Token Details Ви знайдете посилання IPFS або Metadata.
  3. Воно виглядає так: https://ipfs.io/ipfs/QmXX.../metadata.json. Збережіть його.
  4. CID метаданих це частина між /ipfs/ та /metadata.json: QmXX...

Метод 2: Відкрити JSON та витягнути CID медіафайлу

Відкрийте JSON у Вашому браузері. Ви побачите щось на зразок:

JSON метадані { "name": "Ваш твір", "description": "...", "image": "ipfs://QmYY.../nft.mp4" }

Значення поля image (або іноді animation_url) починається з ipfs://, після чого йде інший CID. Це CID медіафайлу. Збережіть і його.

Створіть просту таблицю інвентарю

Для кожного твору запишіть:

  • Назву твору
  • CID JSON метаданих
  • CID файлу медіа (відео або зображення)
  • Адресу контракту і TokenID (щоб потім шукати в Etherscan)

Простої електронної таблиці достатньо. Зробіть це, поки Foundation ще доступний. Якщо зачекаєте, видобути дані стане значно складніше.

Порада

Якщо у Вас є інвентар, який легко скопіювати з Вашого профілю Foundation, беріть його масово. Ви також можете знайти свої токени прямо в Etherscan, шукаючи свій wallet і фільтруючи за NFT.

Крок 06

Запінніть Ваші CID у Filebase

Ось тут і відбувається магія. Filebase знаходить Ваші файли в мережі IPFS та копіює їх на свої вузли.

Процес для кожного твору

  1. Відкрийте бакет, який Ви створили, натиснувши на його ім’я.
  2. Ви побачите три опції: Import CID, New Folder, Upload. Натисніть Import CID.
  3. Відкривається форма. Вставте CID JSON метаданих першого твору.
  4. Дайте йому описове ім’я, наприклад moya-robota-metadata.json.
  5. Підтвердьте натисканням Search and Pin.

Filebase шукатиме CID у мережі IPFS (це займає кілька секунд) та запінить його на свої вузли. Статус зміниться з Pinning (у процесі, помаранчева іконка) на Pinned (підтверджено, зелена іконка).

Повторіть для CID файлу медіа:

  1. Import CID знову.
  2. Вставте CID відео або зображення.
  3. Ім’я: moya-robota-media.mp4 (або правильне розширення).
  4. Підтвердьте.

Рекомендована конвенція іменування

Використовуйте послідовні імена, щоб потім було легко шукати у бакеті. Пропозиція:

  • Сольні роботи: nazva-roboty-metadata.json і nazva-roboty-media.mp4
  • Колаборації: split-prizvyshche-spivavtora-nazva-metadata.json
  • Нумеровані серії: seriya-01-nazva-metadata.json, seriya-02-... (використовуйте ведучі нулі, якщо у Вас більше 9)

Імена в нижньому регістрі, з дефісами замість пробілів, без діакритичних знаків або спеціальних символів. Це уникає проблем з URL та файловими системами.

Приблизний час

Кожен пін займає від кількох секунд (для маленьких JSON) до пари хвилин (для важких відео). Для корпусу з 10-15 робіт плануйте 40 хвилин до 1 години ручної роботи.

Приємна деталь

Якщо Ви пінните CID, який Filebase уже запіннив деінде (тому що інший художник запіннив той самий файл), він пінниться майже миттєво. IPFS не дублює файли, він посилює їх присутність.

Крок 07

Перевірте, що все в порядку

Перш ніж вважати резервне копіювання завершеним, переконайтеся, що файли дійсно доступні з публічної мережі.

Перевірка 1: Усі позначені Pinned

Подивіться на стовпець Status у Вашому бакеті. Усі файли повинні мати зелену іконку та позначку Pinned. Якщо якийсь залишається в Pinning (помаранчевий) після кількох хвилин, зачекайте ще або оновіть сторінку.

Перевірка 2: Доступно через публічний шлюз

Скопіюйте один із Ваших CID і вставте в цей URL, замінивши [CID]:

Перевірити CID https://dweb.link/ipfs/[CID]

Якщо Ви бачите вміст (JSON чи відео), Ваш пін живий у децентралізованій мережі, доступний через будь-який шлюз, не залежно від Foundation чи Filebase.

Перевірка 3: Розумне використання місця

Подивіться на індикатор Storage Вашого бакета. Типове відео NFT важить від 10 до 80 МБ. Якщо у Вас 15 робіт із відео, Ви будете близько 500-800 МБ. Далеко від ліміту в 5 ГБ безкоштовного плану.

Якщо Ви близько до ліміту (тому що у Вас більше робіт або дуже важкі відео), розгляньте можливість пінити лише метадані менш критичних робіт і залишити їхні відео без додаткової резервної копії (вони продовжать жити на інших публічних вузлах IPFS деякий час).

Крок 08

Оновіть посилання на Вашому сайті

Якщо у Вас є особистий сайт або портфоліо з посиланнями на Ваші NFT, ці посилання потрібно змінити. Ті, що вказують на Foundation, помруть.

Що замінити

Шукайте на Вашому сайті посилання на кшталт таких:

https://foundation.app/mint/eth/0x...../tokenID https://fnd-collections.mypinata.cloud/ipfs/QmXX.../metadata.json https://fnd-collections4.mypinata.cloud/ipfs/...

Усі вони припинять працювати. Їх слід замінити стабільними посиланнями на шлюзи IPFS.

Які посилання використовувати

Рекомендую три типи посилань на роботу:

1. Метадані (технічний запис роботи):

https://dweb.link/ipfs/[CID_METADATA]/metadata.json

2. Медіа (відео чи зображення):

https://dweb.link/ipfs/[CID_MEDIA]/nft.mp4

3. Etherscan (верифікація володіння on-chain):

https://etherscan.io/token/[CONTRACT]?a=[TOKEN_ID]

Це третє посилання замінює посилання Foundation. Там, де Ви раніше вказували на маркетплейс, тепер вказуєте на публічний реєстр Ethereum, який ніколи не закривається.

Про шлюзи

Я використовую dweb.link, тому що ним керує Protocol Labs (фонд, не комерційна компанія), він відносно швидкий та нейтральний. Альтернативи: ipfs.io (той самий провайдер, іноді повільніший), cloudflare-ipfs.com (швидко, але залежить від централізованої компанії). Будь-який працює; важливий CID.

Крок 09

Якщо Ваші твори на Arweave (резерв не потрібен)

Деякі твори Foundation використовують Arweave замість IPFS. У них вбудована постійність.

Якщо при відкритті метаданих Вашого твору Ви бачите URL, що закінчуються на arweave.net, або починаються з хешу, за яким іде .arweave.net, Ваш твір живе на Arweave, не на IPFS.

Arweave це інша децентралізована мережа сховища з філософськи іншою моделлю: Ви платите один раз при мінті, і зберігання гарантовано на двісті років через ендавмент-фонд, який продовжує платити вузлам безконечно.

Практичний висновок: якщо одна з Ваших робіт на Arweave, її не потрібно зберігати. Її постійність структурна. Просто позначте це у Вашому інвентарі та переходьте до інших.

Крок 10

Перед повним закриттям Foundation

Останні дії перед вимкненням.

Зняти з продажу непродані роботи

Якщо у Вас є роботи, виставлені на продаж на Foundation, у яких ще немає покупця, розгляньте зняття їх з продажу перед закриттям. Це звільняє токен від ескроу-контракту Foundation і повертає його у Ваш wallet (або wallet мінтера). Коштує трохи газу, але позбавляє від ускладнень потім.

Документуйте співавторів

Якщо у Вас є роботи з on-chain сплітом, нагадайте Вашим співавторам теж зробити це резервне копіювання зі свого боку. Сплит залишається активним, поки існує контракт, але файлам потрібні численні вузли для підтримки, щоб вижити.

Експортуйте кураторську інформацію

Foundation зберігає інформацію, яка не живе on-chain: історію продажів з іменами колекціонерів, редакторські описи, точні дати аукціонів, ставки, підписників. Усе це зникає з Foundation. Робіть скріншоти або експортуйте те, що можете, до закриття.

Розкажіть Вашу історію

Якщо Ви роками перебуваєте в просторі криптомистецтва, Ви свідок розділу культурної історії, який мало хто прожив зсередини. Запишіть те, що пам’ятаєте. Фотографії подій, імена спільноти, упалі платформи, блокування, яких зазнали художники з країн під ембарго. Цей наративний архів такий самий важливий, як CID.

Коли закінчите

Коли Ви запіннили всі роботи, перевірили публічний доступ і оновили посилання на своєму сайті, Ваш корпус переживе закриття Foundation. Робота залишається. Історія продовжується.

Крок 11

А якщо Filebase колись закриється?

Справедливе запитання. Якщо Ви робите резервне копіювання, щоб не залежати від Foundation, чи не переміщуєте Ви просто залежність на іншу компанію? Варто відповісти чесно.

Коротка відповідь

Якби Filebase закрився завтра, Ваші файли не зникають миттєво. IPFS працює через накопичення вузлів, які реплікують той самий контент, а не через єдину точку відмови. Закриття Filebase видаляє лише одну з копій Вашого файлу, не всі.

Крім того, CID універсальні. Вони не належать Filebase. Якщо завтра Ви відкриєте акаунт в іншого провайдера і вставите ті самі CID, у Вас знову буде активний бекап за хвилини. Ваш інвентар (таблиця, яку Ви зібрали на Кроці 05) це все, що Вам потрібно для міграції.

Як насправді працює постійність в IPFS

Файл в IPFS існує, поки хоча б один вузол активно тримає його запінненим. Коли Filebase пінить Ваші CID, його вузли (зазвичай реплікуються тричі в різних локаціях) підтримують файл живим.

Але Filebase не єдиний, у кого є Ваші файли. Щоразу, коли хтось відвідує шлюз IPFS і завантажує Ваш твір, цей шлюз кешує його тимчасово. Кожна взаємодія залишає ефемерні копії. Foundation все ще тримає Ваші CID запінненими до закриття. У мережі є певна природна інерція реплікації.

Три можливі сценарії, якщо Filebase закриється

Сценарій 1, закриття з попереднім повідомленням (очікуваний): серйозні сервіси попереджають за тижні або місяці. У Вас було б достатньо часу для міграції на іншого провайдера: 4EVERLAND, Web3.Storage, Lighthouse. Оскільки у Вас уже є інвентар CID, міграція тривіальна: відкриваєте акаунт, імпортуєте ті самі CID, продовжуєте.

Сценарій 2, раптове закриття без попередження: малоймовірно, але можливо. Ваші файли втрачаються лише якщо одночасно жоден інший вузол їх не має. Для файлів із якою-небудь активністю це статистично рідко.

Сценарій 3, поглинання іншою компанією (найпоширеніший): більша компанія купує меншу і підтримує сервіс із новими умовами. Ваші піни залишаються активними під час переходу. Недавній приклад із екосистеми: KnownOrigin був куплений eBay, із серйозними наслідками, але раніше створені файли залишилися доступними.

Надійна стратегія: мультипровайдерна надлишковість

Філософськи правильна відповідь це не просто вірити, що Filebase не закриється, а не залежати виключно від Filebase. Справжня децентралізація вимагає справжньої надлишковості. Чотири рівні захисту, що реалізуються поступово:

Рівень 1, той, що у Вас уже є: активні піни у Filebase. 5 ГБ безкоштовно. Покриває стандартний випадок.

Рівень 2, паралельна надлишковість: відкрити другий безкоштовний акаунт в іншого провайдера та реплікувати ті самі піни. Надійні варіанти:

  • 4EVERLAND: 5 ГБ безкоштовно, чистий інтерфейс, інший провайдер.
  • Web3.Storage: від Protocol Labs (творці IPFS). 5 ГБ безкоштовно, інституційно дуже стабільний.
  • Lighthouse: модель одноразової оплати за постійне сховище, використовує Filecoin як економічний шар.

З тими самими CID, запінненими в двох різних провайдерів, закриття одного не впливає на інший. Це саме те, що дозволяє децентралізація: не бути прив’язаним до жодного конкретного провайдера.

Рівень 3, локальна фізична копія: завантажити всі медіафайли на Ваш жорсткий диск або зовнішній диск, організовані по папках. Не служить для створення публічних посилань, але гарантує, що якщо всі вузли у світі відмовлять, Ви збережете майстри. Це остання резервна копія, яку роблять серйозні архівісти.

Рівень 4, опціональний та просунутий: запустити власний вузол IPFS з IPFS Desktop або IPFS CLI на одній із Ваших машин. Максимальна технічна автономія. Ваш вузол активний лише коли увімкнено комп’ютер, тому доповнює, але не замінює керовані сервіси.

Прагматична рекомендація

Поки що залишайтеся лише на Filebase (Рівень 1). Цього достатньо для реального короткострокового ризику. Filebase активний з 2019 року і здається інституційно стабільнішим за інших у цей момент.

Через 3-6 місяців, якщо хочете посилити, відкрийте акаунт у 4EVERLAND або Web3.Storage та реплікуйте піни. 15 хвилин роботи, тому що у Вас уже є інвентар з усіма CID. Це дає Вам справжню надлишковість без надмірної інженерії.

Локальну копію на жорсткому диску можете зробити, коли буде час, не терміново, але варто. Власний вузол IPFS лише якщо подобається керувати інфраструктурою.

Філософська нотатка

Існує критична різниця між централізацією та залежністю. Filebase це централізований провайдер (приватна компанія, власні сервери), але Ваше використання Filebase відокремлюване: CID це стандарт IPFS, Ваш інвентар живе на Вашому диску, і Ви можете перейти до іншого провайдера в будь-який момент. Це дуже відрізняється від того, як Ви залежали від Foundation, де закриття Foundation означало втрату посилань, наративу, профілю та спільноти. На цей раз будь-яке закриття було б незручним, але не катастрофічним. Це реальний прогрес.

Поширені запитання

Поширені запитання

Короткі прямі відповіді на те, що художники запитують зараз про закриття Foundation та збереження NFT.

Що відбувається з моїми NFT, коли Foundation закривається?

Токени назавжди залишаються на Ethereum, недоторкані. Під загрозою знаходиться off-chain шар: JSON метаданих та медіафайли (зображення, відео), які зараз живуть на вузлах IPFS Foundation. Коли ці вузли будуть вимкнені, файли можуть стати недоступними, якщо тільки не запінити їх на іншому сервісі. Ваша власність у безпеці; візуальному представленню потрібна резервна копія.

Чи потрібно переносити мої NFT на інший блокчейн?

Ні. NFT залишаються на Ethereum незалежно від долі Foundation. Foundation це інтерфейс маркетплейсу; Ethereum це базовий блокчейн. Вам потрібно лише зберегти off-chain файли, а не переміщати токени.

Filebase справді безкоштовний для резервного копіювання NFT?

Так. 5 ГБ сховища, до 1000 запіннених файлів, виділений шлюз IPFS та функція Import CID, все безкоштовно без банківської картки. Це та комбінація функцій, яку Pinata перевів у платні плани.

Що таке CID IPFS і чому це важливо?

CID (Content Identifier) це криптографічний хеш, який ідентифікує файл в IPFS за його вмістом. Смартконтракт Вашого NFT зберігає посилання на CID, який вказує на метадані, які у свою чергу вказують на CID медіа. CID розв’язуються у контент лише поки вузли тримають файли запінненими. Без пінів немає вмісту, незалежно від існування токена.

Що якщо Filebase теж закриється?

Розглянуто детально на Кроці 11. Коротка версія: CID універсальні, тому можете мігрувати на іншого провайдера IPFS (4EVERLAND, Web3.Storage, Lighthouse) за хвилини з Вашим інвентарем. Для надійності використовуйте мультипровайдерну надлишковість.

Чи потрібно знімати з продажу непродані NFT перед закриттям Foundation?

Рекомендується. Зняття з продажу звільняє токен від ескроу-контракту Foundation і повертає його у wallet мінтера, залишаючи його вільним для повторного продажу десь в іншому місці в майбутньому. Коштує трохи газу, але уникає ускладнень.

Скільки часу займає повний процес резервного копіювання?

Для 10-15 NFT плануйте від 30 хвилин до 2 годин. JSON метадані пінняться за секунди; відеофайли можуть займати по пару хвилин кожен. Процес повторюваний, але не складний, коли готовий інвентар CID.

Що якщо мої NFT на Arweave, а не на IPFS?

Резервне копіювання не потрібне. Arweave забезпечує постійне сховище за дизайном: оплачено один раз при мінті, зберігається близько 200 років через економічний ендавмент, який платить вузлам безконечно.

Чи працює цей посібник для художників поза Foundation?

Так. Той самий процес застосовується до будь-якого NFT на Ethereum, чиї метадані та медіа живуть на IPFS. SuperRare, Zora, Objkt, KnownOrigin (до закриття), Rarible: процес ідентичний. Змінюється лише джерело CID.

Чи можу я пінити NFT інших художників як колекціонер?

Так, і це заохочується. CID публічні за дизайном. Пінінг NFT, які Ви колекціонували, захищає Вашу колекцію від відмови оригінальних вузлів. Розгляньте можливість повідомити художника на знак ввічливості, особливо якщо у Вас є прямий контакт.

Технічне розширення

Як запустити власний вузол IPFS

Цей розділ для художників з певною технічною впевненістю, які хочуть наступний рівень автономії. Це не обов’язково для резервного копіювання Ваших робіт (Filebase достатньо), але якщо Вам близька ідея не залежати від жодного провайдера, ось шлях.

Що означає мати власний вузол

Вузол IPFS це комп’ютер, який бере участь у мережі як ще один член рою. Коли Ви встановлюєте програмне забезпечення, Ваша машина може пінити файли, роздавати їх світу та підтримувати їх живими без залежності від будь-якого комерційного сервісу. Переходите від клієнта провайдера до повноправного учасника мережі. Цифровий еквівалент володіння власною типографією замість залежності від видавця.

Ключова відмінність від Filebase: з Filebase Ви просите компанію пінити Ваші файли на їхніх серверах. Із власним вузлом сервером є Ви.

Важливий компроміс

Ваш вузол роздає файли лише поки Ваш комп’ютер увімкнений та підключений до інтернету. Якщо вимикаєте машину, Ваші файли продовжують існувати на інших вузлах мережі (Filebase, публічні шлюзи, інші сервіси пінінгу), але Ви перестаєте робити свій внесок. Для справді постійної резервної копії Ваш вузол має бути активним майже весь час.

Два справжніх шляхи, залежно від бажаного рівня контролю

Шлях А: IPFS Desktop (найдоступніший)

Графічна програма, яка встановлюється як будь-яка інша програма на macOS, Windows або Linux. Налаштування за 5 хвилин, візуальний інтерфейс, без командного рядка. Ідеально для експериментів і навчання.

Плюси: проста установка, візуальний інтерфейс, можна закрити програму, коли не потрібно.
Мінуси: споживає ОЗУ під час роботи (200-400 МБ), залежить від того, що Ви випадково не закриєте програму, і коли вимикаєте комп’ютер, втрачаєте доступність.

Шлях Б: Виділений Raspberry Pi (серйозний)

Купуєте Raspberry Pi (близько 75-120 USD із корпусом, блоком живлення та SD-картою), встановлюєте на нього IPFS і залишаєте увімкненим 24/7 вдома, підключеним до роутера. Виділений постійний вузол з енергоспоживанням LED-лампи (5-10 Вт, близько 2-3 USD на місяць).

Плюси: справжній постійний вузол, не споживає ресурси Вашого основного комп’ютера, повна технічна автономія.
Мінуси: вимагає початкової покупки, складніша технічна установка (командний рядок), налаштування роутера для зовнішньої доступності.

Рекомендація

Почніть з IPFS Desktop. Вивчіть концепцію без економічних зобов’язань. Якщо через кілька тижнів відчуєте, що справді ним користуєтеся і хочете справжньої постійності, тоді оцініть інвестицію у виділений Raspberry Pi.

Покрокова інструкція з IPFS Desktop

Крок 1: Завантажити інсталятор

Зайдіть на ipfs.tech/install/ipfs-desktop/ (офіційний домен проєкту). Виберіть інсталятор для Вашої операційної системи: macOS, Windows або Linux.

Крок 2: Встановити

На macOS відкрийте .dmg та перетягніть іконку до Applications. На Windows запустіть .exe. На Linux зазвичай це .AppImage. На macOS при першому запуску система може попередити про неперевіреного розробника: зайдіть у Системні налаштування, Безпека, і дайте дозвіл вручну. Це нормально, не означає, що програма небезпечна.

Крок 3: Перший запуск

При першому відкритті програми автоматично відбувається три речі. Перше, створюється унікальна криптографічна ідентичність для Вашого вузла (як постійний ідентифікатор Вашого вузла в мережі). Друге, підключається до глобальної мережі IPFS, і за кілька секунд Ви побачите десятки або сотні підключених пірів (інших вузлів). Третє, відкривається інтерфейс із п’ятьма вкладками: Status, Files, Explore, Peers, Settings.

Крок 4: Запінити перший CID

Перейдіть на вкладку Files. Зверху є кнопка Import. При натисканні розгортається меню з опціями. Виберіть From IPFS (іноді відображається як Add by CID або Import from IPFS). Вставте один із Ваших CID і підтвердьте.

Ваш вузол почне завантажувати файл з інших вузлів, у яких він є (Filebase, публічні шлюзи, будь-яке активне джерело). За секунди або хвилини (залежно від розміру) файл пінниться локально. У цей момент Ваш комп’ютер стає однією з бджіл, які підтримують цей CID.

Крок 5: Перевірити, що працює

Дві прості перевірки. Перша, у Files Ви повинні побачити CID з іконкою шпильки та завантаженим розміром. Друга, відкрийте у браузері:

Локальний шлюз http://localhost:8080/ipfs/[ваш-CID]

Цей localhost:8080 це локальний шлюз, який піднімає Ваш власний вузол. Якщо бачите вміст, Ваш вузол активно роздає файл. Це справжня технічна автономія.

Крок 6: Запінити решту корпусу

Повторіть процес з усіма CID Вашого інвентарю. Для корпусу з 10-15 робіт плануйте від 30 хвилин до 2 годин залежно від Вашого підключення.

Практичні міркування щоденного використання

Споживання ресурсів: IPFS Desktop використовує від 200 до 400 МБ ОЗУ під час роботи. На сучасних комп’ютерах це не проблема, але помітно на машинах з малою пам’яттю. Можете налаштувати ліміти в Settings.

Пропускна здатність: Ваш вузол не тільки завантажує, а й відвантажує іншим вузлам, які просять файли. Якщо у Вас обмежене підключення, налаштуйте ліміти в Settings. З нормальним домашнім підключенням Ви не помітите.

Вимкнення комп’ютера: Ваші CID залишаються живими в мережі, поки інші вузли тримають їх запінненими (Filebase залишається резервною копією). Ваш вузол просто перестає робити внесок тимчасово. При ввімкненні відновлюється автоматично.

Дисковий простір: кожен запіннений CID займає свій розмір на Вашому локальному диску. Розрахунок: для 500 МБ корпусу Foundation Ваш вузол займає 500 МБ. Для великих корпусів Tezos це можуть бути кілька ГБ. Перевірте, що на диску є місце.

Що це дає конкретно

  • Справжня незалежність від Filebase: якщо він закриється завтра з активним Вашим вузлом, Ваші файли залишаться доступними без Вашого втручання.
  • Публікація без посередників: якщо створюєте новий твір і хочете запінити його в IPFS без проходження через будь-який сервіс, робите це напряму зі свого вузла.
  • Технічне розуміння системи: запуск вузла, навіть на кілька тижнів, дає Вам розуміння екосистеми, яке більшість NFT-художників ніколи не набуває.
  • Внесок в екосистему: кожен додатковий вузол зміцнює всю мережу IPFS. Ваша участь це не лише самозахист, це громадська дія.

Природна еволюція в бік Raspberry Pi

Якщо після експериментів з IPFS Desktop відчуваєте, що хочете справжньої постійності, природний шлях такий:

  1. Купити Raspberry Pi 4 (4 або 8 ГБ ОЗУ) з блоком живлення, корпусом та microSD-картою на 128 ГБ. Загальна сума приблизно 100-150 USD.
  2. Підключити його до роутера через ethernet-кабель в якомусь куточку вдома.
  3. Встановити IPFS, дотримуючись туторіалів спеціально для Raspberry Pi (багато англійською, деякі українською та російською).
  4. Налаштувати автоматичний перезапуск при відключенні електрики для підтримки вузла завжди активним.
  5. Опціональне просунуте: налаштувати власний піддомен (наприклад, ipfs.vashartyst.art), що вказує на Ваш Raspberry, щоб мати власний шлюз.

Цей останній крок, власний шлюз з власним доменом, це максимальний суверенітет. Більше не залежите навіть від dweb.link або ipfs.io. Посилання на Вашому сайті будуть Вашими: ipfs.vashartyst.art/ipfs/[CID]/file.mp4.

Ідеальна стратегія поєднує: Filebase як завжди активну керовану резервну копію, плюс IPFS Desktop або Raspberry Pi як власний вузол, що посилює з Вашої власної інфраструктури, плюс локальну копію на жорсткому диску як архів останньої інстанції. Три надлишкові шари, кожен захищений різним дизайном.
