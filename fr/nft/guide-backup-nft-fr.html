Comment sauvegarder vos NFT avant la fermeture de Foundation

Un guide pas-à-pas pour que vos œuvres ne disparaissent pas avec le marketplace. La blockchain se souvient, mais les fichiers ont besoin de quelqu'un qui les soutienne.

Par Ernesto Cisneros Cino · Compositeur, artiste crypto, fondateur d'Impulses.art · Avril 2026

Foundation ferme ses portes. Les tokens resteront sur la blockchain pour toujours, mais les fichiers qui les composent (images, vidéos, métadonnées) vivent sur IPFS, pinnés sur les nœuds de Foundation qui finiront par être mis hors ligne. Lorsque cela arrivera, les liens cesseront de résoudre et les œuvres deviendront des tokens visuellement orphelins, même si tout le reste on-chain sera toujours là.

Ce guide vous accompagne pour sauvegarder l'ensemble de votre corpus sur un service de pinning indépendant et décentralisé, sans payer un centime. À la fin, votre travail sera protégé par une infrastructure que vous contrôlez, pas par une entreprise qui peut fermer demain.

Cela prend entre 30 minutes et 2 heures selon le nombre de pièces. Chaque minute en vaut la peine.

Étape 01

Ce que vous allez faire exactement

Comprendre le problème et la solution avant de commencer vous évitera bien des confusions ensuite.

Le problème

Quand vous avez minté une œuvre sur Foundation, le smart contract a stocké une référence sur Ethereum (un CID, Content Identifier) pointant vers votre fichier JSON de métadonnées sur IPFS. Ce JSON contient le titre, la description, et pointe à son tour avec un autre CID vers le fichier image ou vidéo proprement dit.

Le token est permanent. Mais les fichiers CID n'existent que tant qu'un nœud IPFS les maintient pinnés. Foundation les avait pinnés sur ses propres nœuds. Lorsque ces nœuds seront éteints, si personne d'autre ne pinne ces fichiers, ils disparaîtront du réseau.

La solution

Vous allez pinner ces mêmes CID sur votre propre nœud (en réalité, sur un service gratuit qui agit comme votre nœud). Il ne s'agit pas de copier les fichiers ailleurs, mais de renforcer leur existence à l'intérieur du même réseau IPFS. Le CID reste le même, l'œuvre reste la même, mais elle dispose désormais d'une redondance : elle vit sur les nœuds de Foundation et sur les vôtres.

Lorsque Foundation éteindra ses nœuds, les vôtres resteront actifs. Les liens IPFS continueront de fonctionner. Votre travail survivra à la fermeture du marketplace.

Important

Le token Ethereum (votre propriété, votre historique, vos ventes) n'est jamais en danger. Ce qui est en danger, c'est la couche visuelle et descriptive. C'est cette couche que l'on sauvegarde ici.

Étape 02

Pourquoi Filebase et pas Pinata

Pinata a été pionnier mais son plan gratuit ne fonctionne plus pour ce cas précis. Filebase est l'alternative honnête.

Pinata facture la fonction exacte dont nous avons besoin (Import from IPFS, pinner des CID existants). Avec le plan gratuit vous ne pouvez téléverser que de nouveaux fichiers depuis votre ordinateur, pas pinner des CID qui existent déjà sur le réseau.

Filebase offre 5 Go de stockage, jusqu'à 1 000 fichiers, une passerelle dédiée, et la fonction Import CID, tout inclus dans le plan gratuit sans carte bancaire. C'est cinq fois plus d'espace que Pinata, et la fonction clé est sans restriction.

Filebase utilise également une redondance 3x sur des emplacements géographiquement distincts, ce qui est une vraie redondance, pas du langage marketing.

Une note philosophique

Pinata n'est pas un mauvais service. C'est que votre cas d'usage (pinner des œuvres déjà mintées) est exactement celui que leur modèle commercial actuel pousse vers les plans payants. Filebase traite ce cas comme usage gratuit légitime.

Étape 03

Créez votre compte gratuit Filebase

Cinq minutes, sans carte bancaire.

  1. Allez sur filebase.com et cliquez sur Get Started Free ou Sign Up.
  2. Saisissez votre email et créez un mot de passe solide. Aucune carte requise, aucune information de facturation.
  3. Confirmez votre email via le lien qu'ils envoient.
  4. Connectez-vous au tableau de bord avec votre identifiant et mot de passe.

Vous verrez votre espace de travail vide. L'interface est épurée, uniquement en anglais, mais le flux est simple.

Étape 04

Créez votre bucket d'archive

Un bucket, c'est comme un dossier où vivront vos pins.

  1. Dans le tableau de bord, cliquez sur Buckets dans la navigation latérale.
  2. Cliquez sur Create Bucket.
  3. Donnez-lui un nom unique, par exemple votre-nom-nft-archive. Les noms de buckets sont globaux, donc si le vôtre est pris il faudra en choisir un autre.
  4. Sous Network, sélectionnez IPFS. Ne choisissez pas Sia ni d'autres réseaux, il vous faut IPFS pour vos NFT Foundation.
  5. Confirmez avec Create.
À propos de S3 Private vs Public

Filebase affichera un avertissement disant que les buckets publics nécessitent un plan payant. Ignorez-le, gardez-le sur S3 Private. Cet avertissement concerne l'accès S3 (protocole d'Amazon), qui n'est pas utilisé par les NFT. Vos fichiers resteront accessibles publiquement par CID depuis n'importe quelle passerelle IPFS : ipfs.io, dweb.link, cloudflare-ipfs.com. Le paramètre privé du bucket ne restreint pas cela.

Étape 05

Obtenez les CID de chaque œuvre

Chaque œuvre possède deux CID à identifier : celui du JSON de métadonnées, et celui du fichier image ou vidéo.

Méthode 1 : Depuis Foundation (tant qu'il est encore actif)

  1. Allez sur votre profil Foundation et ouvrez l'une de vos œuvres.
  2. Sous l'onglet Details ou Token Details vous trouverez un lien IPFS ou Metadata.
  3. Il ressemble à https://ipfs.io/ipfs/QmXX.../metadata.json. Enregistrez-le.
  4. Le CID des métadonnées est la partie entre /ipfs/ et /metadata.json : QmXX...

Méthode 2 : Ouvrir le JSON et récupérer le CID du media

Ouvrez le JSON dans votre navigateur. Vous verrez quelque chose comme ceci :

JSON métadonnées { "name": "Votre œuvre", "description": "...", "image": "ipfs://QmYY.../nft.mp4" }

La valeur du champ image (ou parfois animation_url) commence par ipfs:// suivi d'un autre CID. C'est le CID du media. Enregistrez-le aussi.

Constituez un simple tableau d'inventaire

Pour chaque œuvre, notez :

  • Titre de l'œuvre
  • CID du JSON métadonnées
  • CID du fichier media (vidéo ou image)
  • Adresse du contrat et TokenID (pour les retrouver ensuite sur Etherscan)

Un simple tableur suffit. Faites-le pendant que Foundation est encore accessible. Si vous attendez, extraire les données pourrait devenir significativement plus difficile ensuite.

Astuce

Si vous avez un inventaire facile à copier sur votre profil Foundation, récupérez-le en bloc. Vous pouvez aussi chercher vos tokens directement sur Etherscan en recherchant votre wallet et en filtrant par NFT.

Étape 06

Pinnez vos CID sur Filebase

C'est ici que la magie opère. Filebase trouve vos fichiers sur le réseau IPFS et les copie sur ses nœuds.

Processus pour chaque œuvre

  1. Ouvrez le bucket que vous avez créé en cliquant sur son nom.
  2. Vous verrez trois options : Import CID, New Folder, Upload. Cliquez sur Import CID.
  3. Un formulaire s'ouvre. Collez le CID du JSON métadonnées de la première œuvre.
  4. Donnez-lui un nom descriptif, par exemple mon-oeuvre-metadata.json.
  5. Confirmez avec Search and Pin.

Filebase cherchera le CID sur le réseau IPFS (cela prend quelques secondes) et le pinnera sur ses nœuds. Le statut passera de Pinning (en cours, icône orange) à Pinned (confirmé, icône verte).

Répétez pour le CID du fichier media :

  1. Import CID à nouveau.
  2. Collez le CID de la vidéo ou de l'image.
  3. Nom : mon-oeuvre-media.mp4 (ou l'extension correcte).
  4. Confirmez.

Convention de nommage recommandée

Utilisez des noms cohérents pour que votre bucket soit facile à parcourir ensuite. Suggestion :

  • Œuvres solo : titre-oeuvre-metadata.json et titre-oeuvre-media.mp4
  • Collaborations : split-nom-collaborateur-titre-metadata.json
  • Séries numérotées : serie-01-titre-metadata.json, serie-02-... (utilisez des zéros initiaux si vous avez plus de 9)

Noms en minuscules, avec tirets à la place des espaces, sans accents ni caractères spéciaux. Cela évite les problèmes avec les URL et les systèmes de fichiers.

Temps estimé

Chaque pin prend de quelques secondes (pour les petits JSON) à quelques minutes (pour les vidéos lourdes). Pour un corpus de 10 à 15 œuvres, comptez 40 minutes à 1 heure de travail manuel.

Beau détail

Si vous pinnez un CID que Filebase avait déjà pinné ailleurs (parce qu'un autre artiste avait pinné le même fichier), il est pinné presque instantanément. IPFS ne duplique pas les fichiers, il renforce leur présence.

Étape 07

Vérifiez que tout est en ordre

Avant de considérer la sauvegarde terminée, vérifiez que les fichiers sont réellement accessibles depuis le réseau public.

Vérification 1 : Tous marqués Pinned

Regardez la colonne Status dans votre bucket. Tous les fichiers doivent afficher l'icône verte et le texte Pinned. Si l'un reste sur Pinning (orange) après plusieurs minutes, patientez davantage ou rafraîchissez.

Vérification 2 : Accessible depuis une passerelle publique

Copiez l'un de vos CID et collez-le dans cette URL, en remplaçant [CID] :

Tester CID https://dweb.link/ipfs/[CID]

Si vous voyez le contenu (le JSON ou la vidéo), votre pin est vivant sur le réseau décentralisé, accessible depuis n'importe quelle passerelle, sans dépendre de Foundation ni de Filebase.

Vérification 3 : Consommation d'espace raisonnable

Regardez l'indicateur Storage de votre bucket. Une vidéo NFT typique pèse entre 10 et 80 Mo. Si vous avez 15 œuvres avec vidéo, vous serez autour de 500-800 Mo. Bien loin de la limite de 5 Go du plan gratuit.

Si vous approchez de la limite (parce que vous avez plus d'œuvres ou des vidéos très lourdes), envisagez de ne pinner que les métadonnées des œuvres les moins critiques et de laisser leurs vidéos sans sauvegarde supplémentaire (elles resteront sur d'autres nœuds IPFS publics pendant un temps).

Étape 08

Mettez à jour les liens sur votre site

Si vous avez un site personnel ou un portfolio où vous liez vos NFT, ces liens doivent changer. Ceux qui pointent vers Foundation vont mourir.

Ce qu'il faut remplacer

Cherchez sur votre site des liens comme ceux-ci :

https://foundation.app/mint/eth/0x...../tokenID https://fnd-collections.mypinata.cloud/ipfs/QmXX.../metadata.json https://fnd-collections4.mypinata.cloud/ipfs/...

Tous ces liens cesseront de fonctionner. Ils doivent être remplacés par des liens stables de passerelles IPFS.

Quels liens utiliser

Je recommande trois types de liens par œuvre :

1. Métadonnées (fiche technique de l'œuvre) :

https://dweb.link/ipfs/[CID_METADATA]/metadata.json

2. Media (la vidéo ou l'image) :

https://dweb.link/ipfs/[CID_MEDIA]/nft.mp4

3. Etherscan (vérification de propriété on-chain) :

https://etherscan.io/token/[CONTRAT]?a=[TOKEN_ID]

Ce troisième lien remplace le lien de Foundation. Là où vous pointiez vers le marketplace, vous pointez maintenant vers le registre public Ethereum, qui ne ferme jamais.

À propos des passerelles

J'utilise dweb.link parce qu'elle est gérée par Protocol Labs (fondation, pas entreprise à but lucratif), relativement rapide, et neutre. Alternatives valides : ipfs.io (même fournisseur, parfois plus lent), cloudflare-ipfs.com (rapide mais dépend d'une entreprise centralisée). N'importe laquelle fonctionne ; ce qui compte c'est le CID.

Étape 09

Si vos œuvres sont sur Arweave (pas besoin de sauvegarde)

Certaines œuvres Foundation utilisent Arweave au lieu d'IPFS. Elles ont une permanence intégrée.

Si en ouvrant les métadonnées de votre œuvre vous voyez des URL se terminant par arweave.net ou commençant par un hash suivi de .arweave.net, votre œuvre vit sur Arweave, pas sur IPFS.

Arweave est un réseau de stockage décentralisé différent, avec un modèle philosophiquement différent : vous avez payé au mint, et le stockage est garanti pour deux cents ans via un fonds d'endowment qui continue à payer les nœuds indéfiniment.

Conclusion pratique : si l'une de vos œuvres est sur Arweave, inutile de la sauvegarder. Sa permanence est structurelle. Notez-la simplement dans votre inventaire et passez aux autres.

Étape 10

Avant que Foundation ferme complètement

Actions finales avant l'extinction.

Délister les œuvres invendues

Si vous avez des œuvres listées à la vente sur Foundation qui n'ont pas encore d'acheteur, envisagez de les délister avant la fermeture. Cela libère le token du contrat d'escrow de Foundation et le rend à votre wallet (ou à celui du mineur). Cela coûte un peu de gas mais vous évite des complications ensuite.

Documenter les collaborateurs

Si vous avez des œuvres avec split on-chain, rappelez à vos collaborateurs de faire aussi cette sauvegarde de leur côté. Le split reste actif tant que le contrat existe, mais les fichiers ont besoin de plusieurs nœuds qui les soutiennent pour survivre.

Exporter l'information curatoriale

Foundation détient des informations qui ne vivent pas on-chain : historique des ventes avec noms des collectionneurs, descriptions éditoriales, dates exactes des enchères, offres, abonnés. Tout cela disparaît avec Foundation. Faites des captures d'écran ou exportez ce que vous pouvez avant la fermeture.

Racontez votre histoire

Si vous êtes dans l'espace du crypto art depuis des années, vous êtes témoin d'un chapitre d'histoire culturelle que peu ont vécu de l'intérieur. Notez ce dont vous vous souvenez. Photos d'événements, noms de la communauté, plateformes tombées, bannissements subis par les artistes de pays sous embargo. Cette archive narrative compte autant que les CID.

Une fois terminé

Une fois que vous aurez pinné toutes vos œuvres, vérifié l'accès public, et mis à jour les liens de votre site, votre corpus survivra à la fermeture de Foundation. L'œuvre demeure. L'histoire continue.

Étape 11

Et si Filebase ferme un jour, que se passe-t-il ?

Question légitime. Si vous faites des sauvegardes pour ne plus dépendre de Foundation, n'êtes-vous pas simplement en train de déplacer la dépendance vers une autre entreprise ? Cela mérite une réponse honnête.

La réponse courte

Si Filebase fermait demain, vos fichiers ne disparaissent pas instantanément. IPFS fonctionne par accumulation de nœuds qui répliquent le même contenu, pas via un point unique de défaillance. Fermer Filebase ne retire qu'une des copies de votre fichier, pas toutes.

De plus, les CID sont universels. Ils n'appartiennent pas à Filebase. Si demain vous ouvrez un compte chez un autre fournisseur et collez les mêmes CID, vous avez de nouveau une sauvegarde active en quelques minutes. Votre inventaire (le tableur constitué à l'étape 05) est tout ce dont vous avez besoin pour migrer.

Comment fonctionne réellement la persistance sur IPFS

Un fichier sur IPFS existe tant qu'au moins un nœud le maintient activement pinné. Lorsque Filebase pinne vos CID, ses nœuds (typiquement répliqués 3x dans des emplacements distincts) maintiennent le fichier vivant.

Mais Filebase n'est pas le seul à détenir vos fichiers. Chaque fois que quelqu'un visite une passerelle IPFS et charge votre œuvre, cette passerelle la met en cache temporairement. Chaque interaction laisse des copies éphémères. Foundation possède encore vos CID pinnés jusqu'à la fermeture. Le réseau a une certaine inertie de réplication naturelle.

Trois scénarios possibles si Filebase fermait

Scénario 1, fermeture avec préavis (celui attendu) : les services sérieux préviennent avec des semaines ou des mois d'avance. Vous auriez largement le temps de migrer vers un autre fournisseur : 4EVERLAND, Web3.Storage, Lighthouse. Comme vous avez déjà l'inventaire des CID, la migration est triviale : ouvrez un compte, importez les mêmes CID, et continuez.

Scénario 2, fermeture brutale sans préavis : improbable mais possible. Vos fichiers ne se perdent que si, simultanément, aucun autre nœud ne les détient. Pour des fichiers avec n'importe quelle activité, c'est statistiquement rare.

Scénario 3, rachat par une autre entreprise (le plus fréquent) : une entreprise plus grande achète la plus petite et maintient le service avec de nouvelles conditions. Vos pins restent actifs pendant la transition. Exemple récent de l'écosystème : KnownOrigin a été racheté par eBay, avec des conséquences graves, mais les fichiers précédemment mintés sont restés accessibles.

La stratégie robuste : redondance multi-fournisseur

La réponse philosophiquement correcte n'est pas seulement de faire confiance à Filebase pour ne pas fermer, mais de ne pas dépendre exclusivement de Filebase. La décentralisation réelle exige une redondance réelle. Quatre niveaux de protection, implémentables progressivement :

Niveau 1, celui que vous avez déjà : pins actifs sur Filebase. 5 Go gratuits. Couvre le cas standard.

Niveau 2, redondance parallèle : ouvrir un deuxième compte gratuit chez un autre fournisseur et répliquer les mêmes pins. Options solides :

  • 4EVERLAND : 5 Go gratuits, interface épurée, fournisseur différent.
  • Web3.Storage : de Protocol Labs (les créateurs d'IPFS). 5 Go gratuits, institutionnellement très stable.
  • Lighthouse : modèle de paiement unique pour stockage perpétuel, utilise Filecoin comme couche économique.

Avec les mêmes CID pinnés chez deux fournisseurs distincts, la fermeture de l'un n'affecte pas l'autre. C'est précisément ce que la décentralisation permet : ne pas être lié à un fournisseur particulier.

Niveau 3, copie locale physique : télécharger tous les fichiers media sur votre disque dur ou un disque externe, organisés par dossier. Ne sert pas à créer des liens publics, mais garantit que si tous les nœuds du monde échouent, vous conservez les masters. C'est la sauvegarde de dernier recours que font les archivistes sérieux.

Niveau 4, optionnel et avancé : faire tourner votre propre nœud IPFS avec IPFS Desktop ou IPFS CLI sur une de vos machines. Autonomie technique maximale. Votre nœud n'est actif que lorsque votre ordinateur l'est, donc il complète mais ne remplace pas les services gérés.

Recommandation pragmatique

Pour l'instant, restez uniquement sur Filebase (Niveau 1). C'est suffisant pour le risque réel à court terme. Filebase est actif depuis 2019 et paraît institutionnellement plus stable que d'autres en ce moment.

Dans 3 à 6 mois, si vous voulez renforcer, ouvrez un compte sur 4EVERLAND ou Web3.Storage et répliquez les pins. 15 minutes de travail, parce que vous avez déjà l'inventaire avec tous les CID. Cela vous donne une redondance réelle sans sur-ingénierie.

La copie locale sur disque dur, vous pouvez la faire quand vous aurez le temps, pas d'urgence mais cela vaut la peine. Nœud IPFS personnel uniquement si vous aimez gérer de l'infrastructure.

Une note philosophique

Il y a une différence critique entre centralisation et dépendance. Filebase est un fournisseur centralisé (entreprise privée, ses propres serveurs), mais votre usage de Filebase est découplable : les CID sont standard IPFS, votre inventaire vit sur votre disque, et vous pouvez passer à un autre fournisseur à tout moment. Très différent de la manière dont vous dépendiez de Foundation, où la fermeture de Foundation signifiait perdre les liens, la narration, le profil et la communauté. Cette fois, toute fermeture serait ennuyeuse mais pas catastrophique. C'est un vrai progrès.

Questions fréquentes

Questions fréquentes

Réponses brèves et directes à ce que les artistes se demandent maintenant sur la fermeture de Foundation et la préservation des NFT.

Qu'arrive-t-il à mes NFT lorsque Foundation ferme ?

Les tokens restent sur Ethereum pour toujours, intacts. Ce qui est en danger, c'est la couche off-chain : les métadonnées JSON et les fichiers media (images, vidéos) qui vivent actuellement sur les nœuds IPFS de Foundation. Lorsque ces nœuds seront éteints, les fichiers pourraient devenir inaccessibles à moins de les pinner sur un autre service. Votre propriété est en sécurité ; la représentation visuelle a besoin d'une sauvegarde.

Dois-je déplacer mes NFT vers une autre blockchain ?

Non. Les NFT restent sur Ethereum quel que soit le sort de Foundation. Foundation est une interface de marketplace ; Ethereum est la blockchain sous-jacente. Vous devez uniquement sauvegarder les fichiers off-chain, pas déplacer les tokens.

Filebase est-il vraiment gratuit pour sauvegarder les NFT ?

Oui. 5 Go de stockage, jusqu'à 1 000 fichiers pinnés, passerelle IPFS dédiée, et la fonction Import CID, le tout gratuit sans carte bancaire. C'est la combinaison de fonctions que Pinata a déplacée vers les plans payants.

Qu'est-ce qu'un CID IPFS et pourquoi est-ce important ?

Un CID (Content Identifier) est un hash cryptographique qui identifie un fichier sur IPFS selon son contenu. Le smart contract de votre NFT stocke une référence à un CID qui pointe vers les métadonnées, lesquelles pointent à leur tour vers le CID du media. Les CID ne résolvent en contenu que tant que des nœuds ont les fichiers pinnés. Sans pin, pas de contenu, indépendamment de l'existence du token.

Que se passe-t-il si Filebase ferme aussi ?

Traité en détail à l'étape 11. Version courte : les CID sont universels, vous pouvez donc migrer vers un autre fournisseur IPFS (4EVERLAND, Web3.Storage, Lighthouse) en quelques minutes avec votre inventaire. Pour plus de robustesse, utilisez la redondance multi-fournisseur.

Dois-je délister mes NFT invendus avant la fermeture de Foundation ?

Recommandé. Délister libère le token du contrat d'escrow de Foundation et le rend au wallet du mineur, le laissant libre pour être relisté ailleurs à l'avenir. Cela coûte un peu de gas mais évite des complications.

Combien de temps prend le processus complet de sauvegarde ?

Pour 10-15 NFT, comptez 30 minutes à 2 heures. Les métadonnées JSON se pinnent en quelques secondes ; les fichiers vidéo peuvent prendre quelques minutes chacun. Le processus est répétitif mais pas complexe une fois l'inventaire des CID prêt.

Que se passe-t-il si mes NFT sont sur Arweave, pas IPFS ?

Aucune sauvegarde nécessaire. Arweave fournit un stockage permanent par conception : payé une seule fois au mint, préservé pendant environ 200 ans grâce à un endowment économique qui paie les nœuds indéfiniment.

Ce guide fonctionne-t-il pour les artistes hors Foundation ?

Oui. Le même processus s'applique à n'importe quel NFT sur Ethereum dont les métadonnées et le media vivent sur IPFS. SuperRare, Zora, Objkt, KnownOrigin (avant fermeture), Rarible : le flux est identique. Seule la source des CID diffère.

Puis-je pinner les NFT d'autres artistes en tant que collectionneur ?

Oui, et c'est encouragé. Les CID sont publics par conception. Pinner les NFT que vous avez collectionnés protège votre collection de la défaillance des nœuds originaux. Prévenez l'artiste par courtoisie, surtout si vous avez un contact direct.

Extension technique

Comment faire tourner votre propre nœud IPFS

Cette section s'adresse aux artistes ayant une certaine aisance technique et qui souhaitent le niveau suivant d'autonomie. Ce n'est pas nécessaire pour sauvegarder vos œuvres (Filebase suffit), mais si l'idée de ne dépendre d'aucun fournisseur vous attire, voici la voie.

Ce que signifie avoir votre propre nœud

Un nœud IPFS est un ordinateur qui participe au réseau comme un membre de plus de l'essaim. Lorsque vous installez le logiciel, votre machine peut pinner des fichiers, les servir au monde, et les maintenir vivants sans dépendre d'aucun service commercial. Vous passez de client d'un fournisseur à participant à part entière du réseau. L'équivalent numérique de posséder votre propre imprimerie au lieu de dépendre d'un éditeur.

Différence clé avec Filebase : avec Filebase vous demandez à une entreprise de pinner vos fichiers sur ses serveurs. Avec votre propre nœud, vous êtes le serveur.

Compromis important

Votre nœud ne sert les fichiers que tant que votre ordinateur est allumé et connecté à internet. Si vous éteignez la machine, vos fichiers continuent d'exister sur d'autres nœuds du réseau (Filebase, passerelles publiques, autres services de pinning), mais vous cessez de contribuer. Pour une sauvegarde permanente réelle, votre nœud doit être actif presque tout le temps.

Deux voies réelles, selon le degré de contrôle souhaité

Voie A : IPFS Desktop (la plus accessible)

Application graphique que vous installez comme n'importe quel autre programme sur macOS, Windows ou Linux. Mise en place en 5 minutes, interface visuelle, sans ligne de commande. Idéale pour expérimenter et apprendre.

Avantages : installation simple, interface visuelle, vous pouvez fermer l'application quand vous n'en avez pas besoin.
Inconvénients : consomme de la RAM pendant qu'elle tourne (200-400 Mo), dépend du fait de ne pas fermer l'application accidentellement, et lorsque vous éteignez l'ordinateur vous perdez la disponibilité.

Voie B : Raspberry Pi dédié (la plus sérieuse)

Vous achetez un Raspberry Pi (environ 75-120 USD avec boîtier, alimentation et carte SD), vous y installez IPFS, et vous le laissez allumé 24h/24 chez vous connecté au routeur. Nœud permanent dédié avec une consommation électrique équivalente à une ampoule LED (5-10 watts, environ 2-3 USD par mois).

Avantages : nœud permanent réel, ne consomme pas les ressources de votre ordinateur principal, autonomie technique totale.
Inconvénients : requiert un achat initial, installation technique plus complexe (ligne de commande), configuration du routeur pour accessibilité externe.

Recommandation

Commencez par IPFS Desktop. Apprenez le concept sans engagement économique. Si après quelques semaines vous sentez que vous l'utilisez vraiment et voulez une permanence réelle, alors évaluez l'investissement dans un Raspberry Pi dédié.

Pas-à-pas avec IPFS Desktop

Étape 1 : Télécharger l'installateur

Allez sur ipfs.tech/install/ipfs-desktop/ (domaine officiel du projet). Choisissez l'installateur de votre système d'exploitation : macOS, Windows ou Linux.

Étape 2 : Installer

Sur macOS, ouvrez le .dmg et glissez l'icône dans Applications. Sur Windows, exécutez le .exe. Sur Linux, c'est généralement un .AppImage. Sur macOS, la première fois, le système peut vous avertir d'un développeur non vérifié : allez dans Préférences Système → Sécurité et accordez la permission manuellement. C'est normal, cela n'implique pas que le logiciel soit non sécurisé.

Étape 3 : Première exécution

Lorsque vous ouvrez l'application pour la première fois, elle fait trois choses automatiquement. Premièrement, elle crée une identité cryptographique unique pour votre nœud (comme un identifiant permanent de votre nœud sur le réseau). Deuxièmement, elle se connecte au réseau IPFS mondial et en quelques secondes vous verrez des dizaines ou des centaines de peers connectés (d'autres nœuds). Troisièmement, elle ouvre une interface avec cinq onglets : Status, Files, Explore, Peers, Settings.

Étape 4 : Pinner votre premier CID

Allez dans l'onglet Files. En haut, il y a un bouton Import. Lorsque vous cliquez, un menu se déroule avec des options. Choisissez From IPFS (parfois affiché comme Add by CID ou Import from IPFS). Collez l'un de vos CID et confirmez.

Votre nœud commencera à télécharger le fichier depuis d'autres nœuds qui l'ont (Filebase, passerelles publiques, toute source active). En quelques secondes ou minutes (selon la taille), le fichier est pinné localement. À ce moment-là, votre ordinateur est l'une des abeilles qui soutiennent ce CID.

Étape 5 : Vérifier que cela fonctionne

Deux vérifications simples. Un, dans Files vous devriez voir le CID avec une icône d'épingle et la taille téléchargée. Deux, ouvrez dans votre navigateur :

Passerelle locale http://localhost:8080/ipfs/[votre-CID]

Ce localhost:8080 est la passerelle locale que votre propre nœud lève. Si vous voyez le contenu, votre nœud sert activement le fichier. C'est une autonomie technique réelle.

Étape 6 : Pinner le reste de votre corpus

Répétez le processus avec tous les CID de votre inventaire. Pour un corpus de 10-15 œuvres, comptez 30 minutes à 2 heures selon votre connexion.

Considérations pratiques pour l'usage quotidien

Consommation de ressources : IPFS Desktop utilise entre 200 et 400 Mo de RAM en activité. Sur les ordinateurs modernes ce n'est pas un problème, mais c'est perceptible sur des machines avec peu de mémoire. Vous pouvez configurer des limites dans Settings.

Bande passante : votre nœud ne fait pas que télécharger, il téléverse aussi vers d'autres nœuds qui lui demandent des fichiers. Si vous avez une connexion limitée, configurez des limites dans Settings. Avec une connexion domestique normale vous ne le remarquerez pas.

Éteindre l'ordinateur : vos CID restent vivants sur le réseau tant que d'autres nœuds les tiennent pinnés (Filebase reste la sauvegarde). Votre nœud cesse simplement de contribuer temporairement. Lorsque vous rallumez, il reprend automatiquement.

Espace disque : chaque CID pinné occupe sa taille sur votre disque local. Calcul : pour 500 Mo de corpus Foundation, votre nœud occupe 500 Mo. Pour de gros corpus Tezos, cela peut représenter plusieurs Go. Vérifiez que votre disque a de l'espace.

Ce que cela vous apporte concrètement

  • Indépendance réelle de Filebase : s'il fermait demain avec votre nœud actif, vos fichiers resteraient accessibles sans votre intervention.
  • Publication sans intermédiaires : si vous créez une nouvelle œuvre et voulez la pinner sur IPFS sans passer par aucun service, vous le faites directement depuis votre nœud.
  • Compréhension technique du système : faire tourner un nœud, même pendant quelques semaines, vous donne une compréhension de l'écosystème que la plupart des artistes NFT n'acquièrent jamais.
  • Contribution à l'écosystème : chaque nœud supplémentaire renforce l'ensemble du réseau IPFS. Votre participation n'est pas seulement de l'autoprotection, c'est un acte communautaire.

L'évolution naturelle vers Raspberry Pi

Si après avoir expérimenté avec IPFS Desktop vous sentez que vous voulez une permanence réelle, la voie naturelle est :

  1. Acheter un Raspberry Pi 4 (4 ou 8 Go de RAM) avec alimentation, boîtier et carte microSD de 128 Go. Total approximatif 100-150 USD.
  2. Le connecter à votre routeur par câble ethernet dans un coin de votre maison.
  3. Installer IPFS en suivant des tutoriels spécifiques pour Raspberry Pi (abondants en anglais, certains en espagnol).
  4. Configurer un redémarrage automatique en cas de coupure de courant pour maintenir le nœud toujours actif.
  5. Optionnel avancé : configurer votre propre sous-domaine (par exemple ipfs.votreartiste.art) pointant vers votre Raspberry pour avoir votre propre passerelle.

Cette dernière étape, passerelle propre avec domaine propre, est la souveraineté maximale. Vous ne dépendez plus même de dweb.link ou ipfs.io. Les liens de votre site seront les vôtres : ipfs.votreartiste.art/ipfs/[CID]/fichier.mp4.

Pour être clair

Avoir votre propre nœud ne remplace pas Filebase ni ne rend obsolète le travail déjà accompli. Cela le complète. La stratégie idéale combine : Filebase comme sauvegarde gérée toujours active + IPFS Desktop ou Raspberry Pi comme nœud personnel renforçant depuis votre propre infrastructure + copie locale sur disque dur comme archive de dernier recours. Trois couches redondantes, chacune protégée par une conception différente.
