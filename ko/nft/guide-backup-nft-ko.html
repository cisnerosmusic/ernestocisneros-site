Foundation 종료 전 NFT 백업 방법

마켓플레이스가 사라져도 작품을 지키기 위한 단계별 가이드입니다. 블록체인은 기억하지만, 파일은 누군가가 유지해야 합니다.

작성자: Ernesto Cisneros Cino · 작곡가, 크립토 아티스트, Impulses.art 창립자 · 2026년 4월

Foundation이 종료됩니다. 토큰은 블록체인에 영원히 남지만, 토큰을 구성하는 파일(이미지, 비디오, 메타데이터)은 IPFS에 있으며 Foundation의 노드에 핀되어 있습니다. 이 노드들이 오프라인이 되면, 링크는 작동하지 않고 작품은 시각적으로 고아가 된 토큰이 됩니다. 온체인 정보는 그대로 남지만, 시각 콘텐츠는 사라질 수 있습니다.

이 가이드는 독립적이고 탈중앙화된 피닝 서비스에서 전체 코퍼스를 백업하는 방법을 안내합니다. 비용은 들지 않습니다. 완료 후에는 내일 문을 닫을 수 있는 회사가 아니라, 여러분이 제어하는 인프라에 작품이 보호됩니다.

작품 수에 따라 30분에서 2시간 정도 소요됩니다.

단계 01

정확히 무엇을 할 것인가

시작하기 전에 문제와 해결책을 이해하면 혼란을 피할 수 있습니다.

문제

Foundation에서 작품을 민팅했을 때, 스마트 컨트랙트는 이더리움에 CID(Content Identifier) 참조를 저장했습니다. 이 CID는 IPFS에 있는 메타데이터 JSON 파일을 가리킵니다. JSON에는 제목과 설명이 있고, 또 다른 CID를 통해 실제 이미지 또는 비디오 파일을 가리킵니다.

토큰은 영구적입니다. 그러나 CID 파일은 어떤 IPFS 노드가 핀된 상태로 유지하는 동안에만 존재합니다. Foundation은 자체 노드에 파일을 핀해 두었습니다. 이 노드들이 꺼지고 아무도 파일을 핀하지 않으면, 파일은 네트워크에서 사라집니다.

해결책

같은 CID를 여러분의 노드(실제로는 노드 역할을 하는 무료 서비스)에 핀합니다. 파일을 다른 곳에 복사하는 것이 아니라, 같은 IPFS 네트워크 내에서 파일의 존재를 강화하는 것입니다. CID는 그대로 유지되고 작품도 그대로지만, 이제 중복성이 생깁니다. 파일은 Foundation 노드 와 여러분의 노드에 모두 존재합니다.

Foundation이 노드를 끄더라도 여러분의 노드는 활성 상태로 유지됩니다. IPFS 링크는 계속 작동하고, 작품은 마켓플레이스 종료 후에도 유지됩니다.

중요

이더리움 토큰(소유권, 거래 내역, 판매 기록)은 위험하지 않습니다. 위험한 것은 시각 및 설명 계층입니다. 이 가이드는 이 계층을 보호합니다.

단계 02

Filebase를 선택하는 이유

Pinata는 업계 선구자였지만, 무료 플랜은 이 특정 사용 사례에서 더 이상 작동하지 않습니다. Filebase가 현실적인 대안입니다.

Pinata는 우리가 필요로 하는 정확한 기능(Import from IPFS, 기존 CID 핀하기)에 요금을 부과합니다. 무료 플랜에서는 컴퓨터에서 새 파일만 업로드할 수 있고, 네트워크에 이미 존재하는 CID는 핀할 수 없습니다.

Filebase는 5GB 스토리지, 최대 1,000개 파일, 전용 게이트웨이, Import CID 기능까지 모두 무료로 제공하며 신용카드가 필요 없습니다. Pinata보다 5배 많은 공간이고, 핵심 기능에 제한이 없습니다.

Filebase는 또한 지리적으로 분리된 위치에서 3중 중복성을 사용합니다. 마케팅 문구가 아니라 실제 중복성입니다.

참고

Pinata가 나쁜 서비스라는 뜻은 아닙니다. 단지 여러분의 사용 사례(이미 민팅된 작품 핀하기)가 현재 비즈니스 모델에서 유료 플랜으로 이동한 기능입니다. Filebase는 같은 사용 사례를 무료로 제공합니다.

단계 03

Filebase 무료 계정 생성

5분, 신용카드 불필요.

  1. filebase.com에 접속하여 Get Started Free 또는 Sign Up을 클릭합니다.
  2. 이메일을 입력하고 안전한 비밀번호를 생성합니다. 카드 정보나 결제 정보가 필요하지 않습니다.
  3. 수신한 이메일의 링크로 계정을 확인합니다.
  4. 사용자 이름과 비밀번호로 대시보드에 로그인합니다.

빈 작업 공간이 표시됩니다. 인터페이스는 영어로만 제공되지만, 흐름은 단순합니다.

단계 04

아카이브 버킷 생성

버킷은 핀들이 저장될 폴더와 같습니다.

  1. 대시보드에서 사이드 메뉴의 Buckets를 클릭합니다.
  2. Create Bucket을 클릭합니다.
  3. 고유한 이름을 지정합니다. 예: your-name-nft-archive. 버킷 이름은 전역으로 관리되므로, 이미 사용 중이면 다른 이름을 선택해야 합니다.
  4. Network에서 IPFS를 선택합니다. Sia나 다른 네트워크는 선택하지 마십시오. Foundation NFT 백업에는 IPFS가 필요합니다.
  5. Create로 확정합니다.
S3 Private와 Public 설정

Filebase는 공개 버킷이 유료 플랜에서만 가능하다는 알림을 표시합니다. 무시하고 S3 Private로 유지하십시오. 이 알림은 S3 액세스(Amazon 프로토콜)와 관련된 것이며, NFT와는 무관합니다. 파일은 ipfs.io, dweb.link, cloudflare-ipfs.com 등 모든 IPFS 게이트웨이를 통해 CID로 공개적으로 접근 가능합니다. 버킷의 Private 설정은 이에 영향을 주지 않습니다.

단계 05

각 작품의 CID 획득

각 작품에는 두 개의 CID가 있습니다. 메타데이터 JSON용과 이미지/비디오 파일용입니다.

방법 1: Foundation에서 (아직 활성 상태일 때)

  1. Foundation 프로필에서 작품 하나를 엽니다.
  2. Details 또는 Token Details 탭에서 IPFS 또는 Metadata 링크를 찾습니다.
  3. 다음과 같은 형식입니다: https://ipfs.io/ipfs/QmXX.../metadata.json. 저장합니다.
  4. 메타데이터 CID는 /ipfs/와 /metadata.json 사이의 부분입니다: QmXX...

방법 2: JSON을 열어 미디어 CID 추출

브라우저에서 JSON을 엽니다. 다음과 같은 내용이 표시됩니다:

JSON 메타데이터 { "name": "작품명", "description": "...", "image": "ipfs://QmYY.../nft.mp4" }

image 필드의 값(때로는 animation_url)은 ipfs://로 시작하고 또 다른 CID가 이어집니다. 이것이 미디어 CID입니다. 이것도 저장합니다.

간단한 인벤토리 표 작성

각 작품에 대해 다음을 기록합니다:

  • 작품 제목
  • 메타데이터 JSON의 CID
  • 미디어 파일(비디오 또는 이미지)의 CID
  • 컨트랙트 주소와 TokenID (나중에 Etherscan에서 검색용)

간단한 스프레드시트로 충분합니다. Foundation이 아직 접근 가능할 때 작성하십시오. 나중에는 데이터 추출이 훨씬 어려워질 수 있습니다.

팁

Foundation 프로필에 복사하기 쉬운 인벤토리가 있으면 일괄 추출하십시오. Etherscan에서 지갑을 검색하고 NFT로 필터링하여 토큰을 직접 찾을 수도 있습니다.

단계 06

Filebase에 CID 핀하기

이 단계에서 실제 백업이 이루어집니다. Filebase가 IPFS 네트워크에서 파일을 찾아 자체 노드에 복사합니다.

각 작품에 대한 프로세스

  1. 버킷 이름을 클릭하여 생성한 버킷을 엽니다.
  2. 세 가지 옵션이 표시됩니다: Import CID, New Folder, Upload. Import CID를 클릭합니다.
  3. 양식이 열립니다. 첫 작품의 메타데이터 JSON CID를 붙여넣습니다.
  4. 설명적인 이름을 지정합니다. 예: my-artwork-metadata.json.
  5. Search and Pin으로 확정합니다.

Filebase가 IPFS 네트워크에서 CID를 검색하고(몇 초 소요) 자체 노드에 핀합니다. 상태는 Pinning(진행 중, 주황색 아이콘)에서 Pinned(확정, 녹색 아이콘)로 변경됩니다.

미디어 파일 CID에 대해 반복합니다:

  1. Import CID를 다시 클릭합니다.
  2. 비디오 또는 이미지 CID를 붙여넣습니다.
  3. 이름: my-artwork-media.mp4 (또는 올바른 확장자).
  4. 확정합니다.

권장 명명 규칙

나중에 버킷을 쉽게 탐색할 수 있도록 일관된 이름을 사용합니다. 제안:

  • 단독 작품: artwork-title-metadata.json 및 artwork-title-media.mp4
  • 협업: split-collaborator-name-title-metadata.json
  • 번호가 있는 시리즈: series-01-title-metadata.json, series-02-... (9개 이상이면 앞에 0을 붙임)

소문자, 공백 대신 하이픈, 특수문자나 악센트 없이 작성합니다. URL과 파일 시스템 문제를 방지합니다.

예상 시간

각 핀은 몇 초(작은 JSON)에서 몇 분(무거운 비디오)까지 걸립니다. 10-15개 작품의 코퍼스에 대해 40분에서 1시간의 수동 작업을 예상하십시오.

좋은 점

Filebase가 이미 다른 곳에 핀된 CID(다른 아티스트가 같은 파일을 핀한 경우)를 핀하면 거의 즉시 핀됩니다. IPFS는 파일을 복제하지 않고, 존재를 강화합니다.

단계 07

정상 작동 확인

백업을 완료로 간주하기 전에, 파일이 실제로 공개 네트워크에서 접근 가능한지 확인합니다.

확인 1: 모든 파일이 Pinned 상태

버킷의 Status 열을 확인합니다. 모든 파일에 녹색 아이콘과 Pinned 라벨이 표시되어야 합니다. 몇 분이 지나도 Pinning(주황색) 상태인 파일이 있으면 더 기다리거나 페이지를 새로고침합니다.

확인 2: 공개 게이트웨이에서 접근 가능

CID 하나를 복사하여 다음 URL에 붙여넣습니다. [CID] 자리에 실제 CID를 넣습니다:

CID 테스트 https://dweb.link/ipfs/[CID]

콘텐츠(JSON 또는 비디오)가 표시되면, 핀이 탈중앙화 네트워크에서 활성 상태이며 Foundation이나 Filebase 없이도 모든 게이트웨이에서 접근 가능함을 확인합니다.

확인 3: 합리적인 공간 사용

버킷의 Storage 표시기를 확인합니다. 일반적인 NFT 비디오는 10-80MB입니다. 비디오가 있는 작품이 15개라면 500-800MB 정도입니다. 무료 플랜의 5GB 한도에서 충분히 여유가 있습니다.

한도에 가까우면(작품이 더 많거나 비디오가 매우 무거운 경우), 덜 중요한 작품의 메타데이터만 핀하고 비디오는 추가 백업 없이 두는 것을 고려하십시오. 해당 비디오는 다른 공개 IPFS 노드에서 한동안 유지됩니다.

단계 08

웹사이트 링크 업데이트

개인 웹사이트나 포트폴리오에 NFT 링크가 있으면 변경해야 합니다. Foundation을 가리키는 링크는 작동하지 않게 됩니다.

교체 대상

웹사이트에서 다음과 같은 링크를 찾습니다:

https://foundation.app/mint/eth/0x...../tokenID https://fnd-collections.mypinata.cloud/ipfs/QmXX.../metadata.json https://fnd-collections4.mypinata.cloud/ipfs/...

이 링크들은 모두 작동을 멈춥니다. 안정적인 IPFS 게이트웨이 링크로 교체해야 합니다.

사용할 링크

작품당 세 가지 링크 유형을 권장합니다:

1. 메타데이터 (작품의 기술 기록):

https://dweb.link/ipfs/[CID_METADATA]/metadata.json

2. 미디어 (비디오 또는 이미지):

https://dweb.link/ipfs/[CID_MEDIA]/nft.mp4

3. Etherscan (온체인 소유권 확인):

https://etherscan.io/token/[CONTRACT]?a=[TOKEN_ID]

이 세 번째 링크는 Foundation 링크를 대체합니다. 이전에 마켓플레이스를 가리키던 곳에서 이제는 절대 종료되지 않는 이더리움 공개 레지스트리를 가리킵니다.

게이트웨이에 대하여

저는 dweb.link를 사용합니다. Protocol Labs(영리 기업이 아닌 재단)가 운영하며, 상대적으로 빠르고 중립적입니다. 유효한 대안: ipfs.io(동일 제공자, 때때로 더 느림), cloudflare-ipfs.com(빠르지만 중앙화된 회사에 의존). 어떤 것이든 작동합니다. 중요한 것은 CID입니다.

단계 09

작품이 Arweave에 있는 경우 (백업 불필요)

일부 Foundation 작품은 IPFS가 아닌 Arweave를 사용합니다. 이 경우 영속성이 내장되어 있습니다.

작품의 메타데이터를 열었을 때 URL이 arweave.net으로 끝나거나, 해시 뒤에 .arweave.net이 이어지면, 작품은 IPFS가 아닌 Arweave에 있습니다.

Arweave는 다른 모델을 가진 탈중앙화 스토리지 네트워크입니다. 민팅 시 한 번 비용을 지불하면, 노드에 지속적으로 비용을 지급하는 엔다우먼트 펀드를 통해 200년 동안 스토리지가 보장됩니다.

결론: 작품이 Arweave에 있으면 백업할 필요가 없습니다. 영속성이 구조적으로 보장됩니다. 인벤토리에 기록만 하고 다음 작품으로 넘어갑니다.

단계 10

Foundation 완전 종료 전

최종 작업.

판매되지 않은 작품 상장 취소

아직 구매자가 없는 Foundation 판매 목록이 있으면, 종료 전에 상장 취소를 고려하십시오. Foundation의 에스크로 컨트랙트에서 토큰을 해제하고 지갑(또는 민터의 지갑)으로 반환합니다. 약간의 가스 비용이 들지만 이후 복잡한 상황을 피할 수 있습니다.

협업자 기록

온체인 스플릿이 있는 작품이 있으면, 협업자에게도 백업을 진행하도록 알립니다. 스플릿은 컨트랙트가 존재하는 한 활성 상태지만, 파일은 여러 노드의 지원이 필요합니다.

큐레이션 정보 내보내기

Foundation에는 온체인에 있지 않은 정보가 있습니다: 컬렉터 이름이 포함된 판매 기록, 편집 설명, 정확한 경매 날짜, 입찰, 팔로워. 이 모든 정보는 Foundation과 함께 사라집니다. 종료 전에 스크린샷을 찍거나 가능한 것을 내보내십시오.

자신의 이야기 기록

수년간 크립토 아트 분야에 있었다면, 문화 역사의 한 챕터를 내부에서 경험한 몇 안 되는 사람입니다. 기억하는 것을 기록하십시오. 이벤트 사진, 커뮤니티 이름, 사라진 플랫폼, 금수 조치 국가 아티스트에게 가해진 차단. 이 서사적 아카이브는 CID만큼 중요합니다.

완료 시

모든 작품을 핀하고, 공개 접근을 확인하고, 웹사이트 링크를 업데이트하면, 코퍼스는 Foundation 종료 후에도 유지됩니다.

단계 11

Filebase가 언젠가 종료되면 어떻게 되나

타당한 질문입니다. Foundation에 의존하지 않기 위해 백업하는데, 단지 다른 회사로 의존을 옮기는 것 아닌가요?

짧은 답변

Filebase가 내일 종료되더라도, 파일이 즉시 사라지지는 않습니다. IPFS는 단일 장애점을 통하지 않고, 같은 콘텐츠를 복제하는 노드의 축적을 통해 작동합니다. Filebase 종료는 파일의 사본 하나만 제거할 뿐이지, 전체를 제거하지 않습니다.

또한, CID는 보편적입니다. Filebase에 속하지 않습니다. 내일 다른 제공업체에 계정을 만들고 같은 CID를 붙여넣으면, 몇 분 안에 다시 활성 백업이 생깁니다. 5단계에서 만든 인벤토리만 있으면 마이그레이션이 가능합니다.

IPFS에서 영속성이 작동하는 방식

IPFS의 파일은 최소 한 개의 노드가 활성 상태로 핀하고 있는 동안 존재합니다. Filebase가 CID를 핀하면, 해당 노드들(일반적으로 서로 다른 위치에 3배 복제)이 파일을 유지합니다.

하지만 Filebase만 파일을 가지고 있는 것은 아닙니다. 누군가 IPFS 게이트웨이에서 작품을 로드할 때마다, 그 게이트웨이가 파일을 임시로 캐시합니다. 각 상호작용은 일시적 사본을 남깁니다. Foundation도 종료까지 CID를 핀 상태로 유지합니다. 네트워크에는 자연스러운 복제 관성이 있습니다.

Filebase 종료 시 세 가지 시나리오

시나리오 1, 사전 공지를 포함한 종료 (예상되는 경우): 신뢰할 수 있는 서비스는 몇 주 또는 몇 달 전에 공지합니다. 다른 제공업체(4EVERLAND, Web3.Storage, Lighthouse)로 마이그레이션할 시간이 충분합니다. 이미 CID 인벤토리가 있으므로, 마이그레이션은 계정을 만들고 같은 CID를 가져오면 끝납니다.

시나리오 2, 사전 공지 없는 갑작스러운 종료: 가능성은 낮지만 발생할 수 있습니다. 다른 노드가 동시에 파일을 가지고 있지 않은 경우에만 파일이 사라집니다. 활동이 있는 파일은 통계적으로 드문 사례입니다.

시나리오 3, 다른 회사의 인수 (가장 일반적): 더 큰 회사가 작은 회사를 인수하고 새 약관으로 서비스를 유지합니다. 전환 중에도 핀은 활성 상태입니다. 최근 사례: KnownOrigin은 eBay에 인수되었고 정책 변경이 있었지만, 이전에 민팅된 파일은 기술적으로 계속 접근 가능했습니다.

견고한 전략: 멀티 제공업체 중복성

철학적으로 올바른 접근은 Filebase가 종료되지 않을 것이라고 믿는 것이 아니라, Filebase에만 전적으로 의존하지 않는 것입니다. 점진적으로 구현할 수 있는 네 가지 보호 수준:

수준 1, 현재 상태: Filebase의 활성 핀. 5GB 무료. 표준 사용 사례 해결.

수준 2, 병렬 중복성: 다른 제공업체에 두 번째 무료 계정을 만들고 같은 핀을 복제합니다. 견고한 옵션:

  • 4EVERLAND: 5GB 무료, 깔끔한 인터페이스, 다른 제공업체.
  • Web3.Storage: Protocol Labs(IPFS 창설자)의 서비스. 5GB 무료, 제도적으로 매우 안정적.
  • Lighthouse: 영구 스토리지를 위한 일회성 결제 모델. Filecoin을 경제적 계층으로 사용.

같은 CID가 두 개의 다른 제공업체에 핀되어 있으면, 하나의 종료가 다른 하나에 영향을 주지 않습니다.

수준 3, 로컬 물리적 사본: 모든 미디어 파일을 하드 드라이브나 외장 디스크에 폴더별로 정리하여 다운로드합니다. 공개 링크에는 사용되지 않지만, 전 세계 모든 노드가 실패해도 마스터를 보관합니다. 진지한 아키비스트의 최후 수단입니다.

수준 4, 선택적, 고급: 자체 머신에서 IPFS Desktop 또는 IPFS CLI로 자체 IPFS 노드를 실행합니다. 최대의 기술적 자율성. 노드는 컴퓨터가 켜져 있을 때만 활성이므로 관리 서비스를 보완하지만 대체하지는 않습니다.

실용적 권장사항

현재로서는 Filebase만 유지(수준 1)하는 것으로 충분합니다. 단기 위험에 대응하기에 충분합니다. Filebase는 2019년부터 운영되고 있으며 현재 다른 서비스보다 제도적으로 안정적으로 보입니다.

3-6개월 후 강화를 원하면, 4EVERLAND 또는 Web3.Storage에 계정을 만들고 핀을 복제합니다. 이미 모든 CID가 있는 인벤토리가 있으므로 15분의 작업으로 실제 중복성을 확보할 수 있습니다.

하드 드라이브의 로컬 사본은 시간이 있을 때 하면 됩니다. 급하지는 않지만 가치가 있습니다. 자체 IPFS 노드는 인프라 관리를 즐기는 경우에만 권장합니다.

중요한 구분

중앙화와 의존성은 다릅니다. Filebase는 중앙화된 제공업체(사설 회사, 자체 서버)이지만, Filebase에 대한 의존은 분리 가능합니다. CID는 IPFS 표준이고, 인벤토리는 사용자 디스크에 있으며, 언제든지 다른 제공업체로 이동할 수 있습니다. Foundation에 대한 의존과는 다릅니다. Foundation 종료는 링크, 서사, 프로필, 커뮤니티의 손실을 의미했습니다. 이번에는 어떤 종료라도 불편할 뿐, 재앙은 아닙니다.

FAQ

자주 묻는 질문

Foundation 종료와 NFT 보존에 대한 일반적인 질문에 대한 짧고 직접적인 답변.

Foundation이 종료되면 제 NFT는 어떻게 되나요?

토큰은 이더리움에 영원히 유지됩니다. 위험한 것은 오프체인 계층입니다. 현재 Foundation IPFS 노드에 있는 JSON 메타데이터와 미디어 파일(이미지, 비디오)입니다. 이 노드들이 종료되면, 다른 서비스에 핀하지 않는 한 파일에 접근할 수 없게 될 수 있습니다. 소유권은 안전하지만, 시각적 표현에는 백업이 필요합니다.

NFT를 다른 블록체인으로 옮겨야 하나요?

아니요. Foundation의 운명과 무관하게 NFT는 이더리움에 남습니다. Foundation은 마켓플레이스 인터페이스이고, 이더리움은 기반 블록체인입니다. 오프체인 파일만 백업하면 되며, 토큰 자체는 이동할 필요가 없습니다.

Filebase는 정말 NFT 백업에 무료인가요?

네. 5GB 스토리지, 최대 1,000개 핀 파일, 전용 IPFS 게이트웨이, Import CID 기능까지 모두 신용카드 없이 무료입니다. Pinata가 유료 플랜으로 이동한 기능 조합입니다.

IPFS CID는 무엇이며 왜 중요한가요?

CID(Content Identifier)는 콘텐츠에 기반하여 IPFS의 파일을 고유하게 식별하는 암호화 해시입니다. NFT의 스마트 컨트랙트는 메타데이터를 가리키는 CID 참조를 저장하고, 메타데이터는 미디어 CID를 가리킵니다. CID는 노드가 파일을 핀하고 있는 동안에만 콘텐츠로 해결됩니다. 핀이 없으면 토큰 존재 여부와 관계없이 콘텐츠가 없습니다.

Filebase도 종료되면 어떻게 되나요?

11단계에서 자세히 다룹니다. 요약: CID는 보편적이므로 인벤토리를 사용하여 몇 분 안에 다른 IPFS 제공업체(4EVERLAND, Web3.Storage, Lighthouse)로 마이그레이션할 수 있습니다. 견고성을 위해 멀티 제공업체 중복성을 사용합니다.

Foundation 종료 전에 판매되지 않은 NFT를 상장 취소해야 하나요?

권장합니다. 상장 취소는 Foundation의 에스크로 컨트랙트에서 토큰을 해제하고 민터의 지갑으로 반환하여, 다른 곳에서 재상장할 수 있게 합니다. 약간의 가스 비용이 들지만 이후 복잡한 상황을 피할 수 있습니다.

전체 백업 프로세스에 얼마나 걸리나요?

10-15개 NFT의 경우 30분에서 2시간 정도 예상하십시오. JSON 메타데이터는 몇 초 안에 핀됩니다. 비디오 파일은 각각 몇 분이 걸릴 수 있습니다. CID 인벤토리가 준비되면 반복적이지만 복잡하지 않은 프로세스입니다.

NFT가 IPFS가 아닌 Arweave에 있으면 어떻게 되나요?

백업이 필요 없습니다. Arweave는 설계에 의한 영구 스토리지를 제공합니다. 민팅 시 한 번 지불하면, 노드에 지속적으로 비용을 지급하는 엔다우먼트를 통해 약 200년 동안 보존됩니다.

이 가이드는 Foundation 외의 아티스트에게도 적용되나요?

네. 메타데이터와 미디어가 IPFS에 있는 이더리움의 모든 NFT에 동일한 프로세스가 적용됩니다. SuperRare, Zora, Objkt, KnownOrigin(종료 전), Rarible: 흐름은 동일합니다. CID의 출처만 다릅니다.

컬렉터로서 다른 아티스트의 NFT를 핀할 수 있나요?

네, 권장됩니다. CID는 설계상 공개됩니다. 수집한 NFT를 핀하면 원본 노드의 실패로부터 컬렉션을 보호할 수 있습니다. 특히 직접 연락이 가능한 경우 아티스트에게 알리는 것이 예의입니다.

기술 확장

자체 IPFS 노드 실행

이 섹션은 기술적 숙련도가 있고 더 높은 수준의 자율성을 원하는 아티스트를 위한 것입니다. 작품 백업에는 필수가 아닙니다(Filebase로 충분합니다). 어떤 제공업체에도 의존하지 않는 것이 목표라면 이 경로를 따르십시오.

자체 노드 소유의 의미

IPFS 노드는 네트워크 참여자로서 작동하는 컴퓨터입니다. 소프트웨어를 설치하면 여러분의 머신은 파일을 핀하고, 전 세계에 제공하며, 상업 서비스 없이 유지할 수 있습니다. 제공업체의 클라이언트에서 네트워크의 완전한 참여자로 전환됩니다.

Filebase와의 주요 차이점: Filebase에서는 회사에 파일을 자체 서버에 핀하도록 요청합니다. 자체 노드에서는 여러분이 서버입니다.

중요한 트레이드오프

노드는 컴퓨터가 켜져 있고 인터넷에 연결된 동안에만 파일을 제공합니다. 머신을 끄면 파일은 네트워크의 다른 노드(Filebase, 공개 게이트웨이, 기타 핀 서비스)에서 계속 존재하지만, 여러분은 더 이상 기여하지 않습니다. 실질적인 영구 백업을 위해서는 노드가 거의 항상 활성 상태여야 합니다.

제어 수준에 따른 두 가지 경로

경로 A: IPFS Desktop (가장 접근하기 쉬움)

macOS, Windows, Linux에서 다른 프로그램과 같이 설치하는 그래픽 애플리케이션. 5분 설정, 시각적 인터페이스, 명령줄 불필요. 실험과 학습에 이상적.

장점: 간단한 설치, 시각적 인터페이스, 필요 없을 때 앱 종료 가능.
단점: 실행 중 RAM 소비(200-400 MB), 앱을 실수로 종료하지 않아야 함, 컴퓨터 종료 시 가용성 손실.

경로 B: 전용 Raspberry Pi (본격적인 옵션)

Raspberry Pi(케이스, 전원 공급 장치, SD 카드 포함 약 75-120 USD)를 구입하여 IPFS를 설치하고, 집에서 라우터에 연결한 상태로 24/7 켜 둡니다. LED 전구 수준의 전력 소비(5-10 와트, 월 약 2-3 USD)로 전용 영구 노드.

장점: 실제 영구 노드, 주 컴퓨터 리소스 사용 없음, 완전한 기술적 자율성.
단점: 초기 구매 필요, 더 복잡한 기술 설치(명령줄), 외부 접근을 위한 라우터 구성.

권장사항

IPFS Desktop으로 시작하십시오. 경제적 약속 없이 개념을 배웁니다. 몇 주 후 실제로 사용하고 영구성이 필요하다고 느끼면, 전용 Raspberry Pi 투자를 검토합니다.

ipfs.tech/install/ipfs-desktop/(프로젝트 공식 도메인)로 이동합니다. 운영 체제 설치 프로그램 선택: macOS, Windows, Linux.

단계 2: 설치

macOS에서는 .dmg를 열고 아이콘을 Applications로 드래그합니다. Windows에서는 .exe를 실행합니다. Linux에서는 일반적으로 .AppImage입니다. macOS 처음 실행 시 시스템이 검증되지 않은 개발자에 대해 경고할 수 있습니다. 시스템 환경설정 → 보안에서 수동으로 권한을 부여합니다. 정상이며 소프트웨어가 안전하지 않다는 뜻은 아닙니다.

단계 3: 첫 실행

처음 애플리케이션을 열면 세 가지가 자동으로 발생합니다. 첫째, 노드에 대한 고유한 암호화 ID가 생성됩니다(네트워크에서 노드의 영구 ID). 둘째, 글로벌 IPFS 네트워크에 연결되며 몇 초 안에 연결된 수십에서 수백 개의 피어(다른 노드)가 표시됩니다. 셋째, 다섯 개 탭이 있는 인터페이스가 열립니다: Status, Files, Explore, Peers, Settings.

단계 4: 첫 CID 핀하기

Files 탭으로 이동합니다. 상단에 Import 버튼이 있습니다. 클릭하면 옵션 메뉴가 펼쳐집니다. From IPFS(때로는 Add by CID 또는 Import from IPFS로 표시)를 선택합니다. CID 하나를 붙여넣고 확정합니다.

노드가 파일을 가진 다른 노드(Filebase, 공개 게이트웨이, 활성 소스)에서 파일을 다운로드하기 시작합니다. 몇 초에서 몇 분(크기에 따라) 후 파일이 로컬에 핀됩니다. 그 순간 여러분의 컴퓨터는 해당 CID를 지원하는 네트워크의 일원이 됩니다.

단계 5: 작동 확인

두 가지 간단한 확인. 첫째, Files에서 핀 아이콘과 다운로드된 크기가 있는 CID가 표시되어야 합니다. 둘째, 브라우저에서 엽니다:

로컬 게이트웨이 http://localhost:8080/ipfs/[your-CID]

localhost:8080은 여러분의 노드가 실행하는 로컬 게이트웨이입니다. 콘텐츠가 표시되면 노드가 파일을 활성적으로 제공하고 있는 것입니다. 이것이 실질적인 기술적 자율성입니다.

단계 6: 나머지 코퍼스 핀하기

인벤토리의 모든 CID로 프로세스를 반복합니다. 10-15개 작품의 경우 연결 속도에 따라 30분에서 2시간을 예상하십시오.

일상 사용의 실용적 고려사항

리소스 소비: IPFS Desktop은 활성 상태에서 200-400MB의 RAM을 사용합니다. 최신 컴퓨터에서는 문제가 되지 않지만, 메모리가 적은 머신에서는 눈에 띕니다. Settings에서 제한을 구성할 수 있습니다.

대역폭: 노드는 다운로드뿐만 아니라 파일을 요청하는 다른 노드에 업로드도 합니다. 연결이 제한적이면 Settings에서 제한을 구성하십시오. 일반 가정용 연결에서는 알아차리지 못합니다.

컴퓨터 종료: CID는 다른 노드가 핀 상태로 유지하는 한 네트워크에서 활성 상태로 유지됩니다(Filebase가 백업으로 남음). 노드는 단지 임시로 기여를 중단합니다. 다시 켜면 자동으로 재개됩니다.

디스크 공간: 각 핀된 CID는 로컬 디스크에서 해당 크기를 차지합니다. 계산: 500MB 크기의 Foundation 코퍼스면 노드가 500MB를 차지합니다. 큰 Tezos 코퍼스의 경우 몇 GB가 될 수 있습니다. 디스크에 공간이 있는지 확인하십시오.

얻는 것

  • Filebase로부터의 실질적 독립: 내일 Filebase가 종료되어도 활성 노드가 있으면 파일은 개입 없이 접근 가능합니다.
  • 중개자 없는 출판: 새 작품을 만들어 IPFS에 핀하고 싶으면 서비스 없이 노드에서 직접 수행합니다.
  • 시스템의 기술적 이해: 몇 주만 노드를 실행해도 대부분의 NFT 아티스트가 얻지 못하는 생태계에 대한 이해를 얻습니다.
  • 생태계 기여: 각 추가 노드는 전체 IPFS 네트워크를 강화합니다. 참여는 자기 보호뿐만 아니라 커뮤니티 행동이기도 합니다.

Raspberry Pi로의 자연스러운 진화

IPFS Desktop으로 실험한 후 실제 영구성을 원하면 자연스러운 경로는:

  1. Raspberry Pi 4(4 또는 8GB RAM), 전원 공급 장치, 케이스, 128GB microSD 카드 구매. 대략 100-150 USD.
  2. 집 한구석에서 이더넷 케이블로 라우터에 연결합니다.
  3. Raspberry Pi용 튜토리얼(영어에 많음, 일부 스페인어)에 따라 IPFS를 설치합니다.
  4. 정전 시 노드를 항상 활성 상태로 유지하기 위해 자동 재시작을 구성합니다.
  5. 고급 옵션: Raspberry Pi를 가리키는 자체 서브도메인(예: ipfs.yourartist.art)을 구성하여 자체 게이트웨이를 만듭니다.

이 마지막 단계, 자체 도메인으로 자체 게이트웨이를 구축하는 것은 최대의 자율성입니다. dweb.link나 ipfs.io에도 의존하지 않습니다. 웹사이트의 링크는 자체 링크가 됩니다: ipfs.yourartist.art/ipfs/[CID]/file.mp4.

명확히 하기 위해

자체 노드를 갖는 것이 Filebase를 대체하거나 이미 수행된 작업을 무용지물로 만들지 않습니다. 보완합니다. 이상적인 전략은 항상 활성 관리 백업인 Filebase, 자체 인프라에서 강화하는 IPFS Desktop 또는 Raspberry Pi 자체 노드, 최후 보루 아카이브인 하드 드라이브 로컬 사본을 조합합니다. 세 개의 중복 계층, 각각 다른 설계로 보호됩니다.
